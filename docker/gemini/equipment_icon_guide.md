# 장비 아이템 아이콘 가이드 (icon.equip.*)

단일 출처: 프롬프트·규칙 상수는 `docker/gemini/style_guide.mjs`의 "장비 아이템 아이콘" 섹션(`EQUIP_*`, `equipJob`, `QA_CHECKLIST.equip`)에 있다. 이 문서는 사람이 읽는 요약이다. 둘이 다르면 `style_guide.mjs`가 기준이다.

## 1. 대상
- 슬롯 5종 x 등급 C/B/A/S = 20개 + `accessory_c2 / accessory_b2 / accessory_a2` = 코드 23개.
- 이름과 문화권 배정은 `database/data/equipment_text_proposal.json`(송서사)을 따른다. 생성 시 자동으로 읽는다.

## 2. 크기와 그림체
| 항목 | 규칙 |
|---|---|
| 마스터 | 128x128 PNG, 투명 배경. 기존 `icon.*`(128) 규격과 같음 |
| 축소본 | 64x64 PNG를 lanczos로 미리 축소해 함께 제공. 게임이 `pixelArt:true`라서 런타임 축소는 최근접 보간이 되어 거칠어지므로 미리 축소한 파일을 쓴다 |
| 표시 크기 | 인벤토리·장착 슬롯은 64, 상세 패널은 128. 48 이하로 줄여 써야 하면 64 파일을 쓴다(시험에서 48 표시까지 형태가 읽히는 것을 확인함) |
| 그림체 | 기존 UI 아이콘과 같은 애니메이션풍 셀 셰이딩 일러스트. 도트가 아니다. 광원은 왼쪽 위 |
| 외곽선 | 짙은 남흑색(#14182A) 한 겹(폭의 약 2.5%). 기존 UI 아이콘의 금색 외곽 테두리는 쓰지 않는다. 금색 테두리가 S등급 금색 프레임과 겹치고, 모든 아이템이 "금색"으로 보이기 때문이다 |
| 여백 | 128 기준으로 사방 14px(64는 7px). 프레임 테두리(4px)를 침범하지 않는다 |

## 3. 슬롯 구분(실루엣, 등급과 무관하게 고정)
| 슬롯 | 실루엣 규칙 |
|---|---|
| helm 투구 | 투구만, 3/4 정면, 위는 둥글거나 뾰족한 덮개, 아래는 열린 형태. 머리·얼굴 없음 |
| armor 갑옷 | 몸통 갑옷만, 정면, 넓은 어깨 + 좁아지는 허리(역사다리꼴), 목둘레가 열려 있음 |
| gloves 장갑 | 오른손 한 짝, 손등이 보이고 손가락은 위, 시계 방향으로 15도 기울임, 커프는 아래 |
| boots 신발 | 오른발 한 짝, 옆모습, 발끝은 화면 왼쪽, 발바닥 선은 수평 |
| accessory 장신구 | 작은 장신구 1개를 75%까지 확대. 끈·고리·사슬이 반드시 보이고 전부 프레임 안에 들어온다 |

사람 신체(손·발·얼굴)와 마네킹·받침대는 그리지 않는다.

## 4. 등급 구분
**프레임(색, 코드로 그림)과 재질 사다리(그림)를 함께 쓴다.**
- 프레임은 생성하지 않는다. `pp_equip.mjs`가 SVG로 그린다(`deco.equip_frame.<c|b|a|s>`, 128/64).
- 색은 영웅 등급 표시 색(`resources/js/game/rarity.js` RARITY_COLOR)과 같은 값을 쓴다: C `#8B97A8` 회청, B `#2FB5A6` 청록, A `#B06AD8` 보라, S `#F0B23C` 금.
- 색각 보조: 하단 마름모 점 개수(C1·B2·A3·S4). S는 네 모서리 장식과 안쪽 빛 테두리를 추가한다.
- 대비(WCAG, 비텍스트 기준 3:1): panel.base(#101C3A) 위 테두리 C 5.7 / B 6.6 / A 4.7 / S 8.9. 프레임 중심 배경과 아이템 외곽선의 대비는 3.3~4.0이다.
- 재질 사다리:
  - C: 가죽·삼베·무쇠·나무, 무광, 장식 없음
  - B: 손질된 철·염색 천, 리벳, 포인트 색 1가지
  - A: 광택 강철·은 + 금 테두리 소량, 문화권 문양 1가지, 보석 0~1개
  - S: 금·백은·비취, 정교한 문양, 보석 1~3개, 돋보이는 장식 1개. 발광은 그리지 않는다(프레임이 담당)

### 보라 금지 규칙과의 관계
기존 "보라·분홍·마젠타 금지"는 크로마키 오염과 초상화 고증 때문에 생긴 **생성 그림 내용**에 대한 규칙이다. 장비 아이템 그림에도 그대로 적용한다(보석은 청·적·녹·호박색으로 그린다). A등급 보라는 코드로 그리는 프레임에만 쓰므로 이 규칙과 충돌하지 않는다.

주의: `public/assets/ui/design_spec.json`의 `rankBorder`(N/R/SR/SSR)는 구 체계라서 현재 C/B/A/S 색과 다르다. 정리가 필요하다(윤프론·팀장 확인).

## 5. 문화권 변형 방식
슬롯 실루엣과 등급 재질 사다리는 그대로 두고, **형태 세부·문양·재질 조합만** 바꾼다. 아이템별 문구는 `EQUIP_DESC`, 문화권 공통 문구는 `EQUIP_CULTURE`에 있다. 전부 고증 `verify` 수준의 양식 모티프다.
- korea: 남색·붉은색·놋쇠, 징 박힌 천, 매듭·술, 구름·덩굴 문양
- japan: 검은 옻칠, 실로 엮은 소찰, 남색·붉은 끈. 가문 문장 금지
- china: 비늘·소찰, 붉은 술, 옥, 청동, 구름 문양. 한자·용 머리 금지
- middle_east: 사슬, 금실 기하 무늬, 놋쇠, 뾰족한 형태. 초승달·글자·종교 상징 금지
- europe: 판금, 리벳, 가죽 끈, 덩굴 음각, 붉은 보석. 문장·십자·글자 금지

모든 문화권에서 고정관념을 과장하지 않고, 다른 문화권 장식을 섞지 않는다.

## 6. 키·파일·manifest
- 키: `icon.equip.<code>`(아이템, 투명), `deco.equip_frame.<c|b|a|s>`(프레임)
- 파일(본 생산 예정 위치): `public/assets/equip/icons/{128,64}/<code>.png`, `public/assets/equip/frames/{128,64}/<r>.png`, `public/assets/equip/atlas/equip_icons_{128,64}.{png,json}`
- 시험본 위치: `public/assets/equip_trial/`(본 manifest에 병합하지 않고 `manifest_fragment.json`으로 둔다)
- manifest 필드: `key, path, path64, atlas{128,64}, type(icon), size, variants, alpha, bytes, bytes64, slot, slot_ko, rarity, culture, name_ko, frame, generator{model,api,size,script}, prompt_ref, license, qa{auto, verdict, issues}, verify`

## 7. 로딩 권장
- 아틀라스 사용을 권장한다(Phaser JSON Hash). 23개 x 128이면 768x512 한 장(6열)이고, 64판은 384x256이다. 프레임 이름은 키 그대로(`icon.equip.<code>`)다.
- 프레임 4종은 개별 PNG로 둔다.
- 합성 순서는 프레임 → 아이템(같은 크기, 같은 좌상단)이다. 장착 안 된 빈 슬롯은 C 프레임을 alpha 0.4로 깔고 기존 `icon.*`나 슬롯 이름 텍스트를 올린다(FE 판단).
- 인벤토리·장비 화면에 들어갈 때 아틀라스 1회만 로드한다. 전투 씬에서는 프리로드하지 않는다.

## 8. 프롬프트 템플릿(Gemini 이미지 API, 1K, 1:1)
```
게임 장비 아이템 아이콘 1개: <슬롯> '<이름>'.
형태: <EQUIP_DESC[code]>.
슬롯 실루엣: <EQUIP_SLOT[slot].shape>.
<EQUIP_RARITY_MAT[등급]>.
문화권 모티프: <EQUIP_CULTURE[culture]>.
스타일: <EQUIP_STYLE>
구도: <EQUIP_COMP>
<KEY_BG(마젠타 단색, 본체에 마젠타·분홍·자주 금지)>
금지: <EQUIP_NEGATIVE>
```
- **참조 이미지를 붙이지 않는다.** 시험에서 기존 UI 아이콘 시트를 참조로 붙였더니 5장 중 2장이 참조 시트를 그대로 복제했다.
- 실행 예: `docker run --rm --env-file .env -e MAX_CALLS=23 -v "$PWD":/app -w /app node:22 node docker/gemini/gen.mjs equip`. 호출은 순차로 하고 간격 5초, 타임아웃 120초, 429/5xx는 2회 재시도, 기록은 `calls_log.json`에 남는다.

## 9. 후처리
`docker/gemini/pp_equip.mjs <category> <outDir>` 순서:
1. 마젠타 키(pp.mjs와 같은 알고리즘, grow 3)와 despill
2. 400px 미만 잡티 제거
3. bbox 크롭
4. 128/64 맞춤(lanczos3)
5. 프레임 SVG 렌더
6. 아틀라스
7. QA 패널(`preview/equip_qa_panel.png`: 128, 64 x2, 48 x2, 등급 4종 비교, 흰 바탕 헤일로 점검)
8. manifest 조각

자동 지표: 잔여 마젠타 px, 보라 비율, 원본 가장자리 접촉 px.

## 10. 자체 QA 체크리스트
`QA_CHECKLIST.equip` 참조.
- 64/48에서 슬롯이 구분되는가
- C→S 재질 차이가 보이는가
- 외곽선은 남흑색 한 겹이고 금테·발광이 없는가
- 광원 방향과 그림체가 통일되어 있는가
- 보라·분홍·마젠타가 없고 잔여 마젠타가 0인가(흰 바탕·남색 바탕 모두)
- 글자·문장·종교 상징·신체가 없는가
- 여백 안에 들어오는가
- 문화권 배정과 일치하는가(고증 verify)
