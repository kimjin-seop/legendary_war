# 영웅 칭호 v2 제안 노트 (송서사, 2026-11-01)

산출: `database/data/hero_titles_v2_proposal.json` (101명, 키=기존 `hero_titles.json` titles 키). 기존 파일·DB·앱 코드 미수정.

## 구조 (박백엔 반영용)
- 현행 표시 규칙은 `GameData::displayName` = `${title} ${short_name ?? name_ko}` 이고 DB에는 `title`, `short_name`(각 varchar 32)만 있다. `display_name`은 계산값이다.
- 따라서 v2도 title = 이름 앞에 붙는 칭호(접두), short_name = 칭호 뒤에 붙는 짧은 이름(없으면 name_ko). `titles.<code>.title / short_name`만 시드에 쓰면 된다. `display_name`·`alternatives`·`basis` 등은 검수·도감용 참고 필드.
- 반영 방법 제안: `GameSeed::syncHeroTitles`가 읽는 경로를 v2 파일로 교체(또는 `titles` 맵을 `hero_titles.json`에 병합). 이때 v2의 short_name=null은 DB null(=name_ko 사용)로 들어가므로 현행 동작과 동일하다. `troop_names`는 v2에 포함하지 않았으므로 기존 파일의 해당 블록을 유지해야 한다.
- 최대 title 길이 14자, short_name 6자 → varchar(32) 안전.

## 길이 규칙 점검
- 요청 규칙(title 8~14자)은 현행 UI 구조(칭호+이름 한 줄)와 충돌한다. 기존 데이터는 공백 제외 6자 이하로 설계됐고 title 14자 + 이름이면 한 줄이 20자 안팎이 된다. 그래서 title은 4~14자, 가능한 한 10자 이내로 쓰고 좁은 화면은 기존 display_rule대로 short_name만 표시하는 것을 전제로 했다. 사람 결정 필요.
- title 길이(공백 포함): 7자 이하 41건, 8~10자 49건, 11~14자 11건, 15자 이상 0건. 8~14자 충족 60건 / 미충족 41건(모두 7자 이하: 직함형 `서산대사`, `서초패왕`, `한 고조` 등 실제 호칭이 원래 짧은 경우).
- 11자 이상(UI 확인 권장): 대몽골 울루스의 창건자, 콘스탄티노폴리스 공략 술탄(14), 안데스 해방군 사령관, 놀리 메 탄헤레 저자, 프랑스·잉글랜드 왕비, 무적함대 시대의 여왕, 7년전쟁의 프로이센 왕, 러시아 제국 초대 황제, 가마쿠라 막부 초대 쇼군, 아바스의 제5대 칼리프, 만지케르트 승전 군주.
- display_name 17자 이상(전투 UI 한 줄 폭 확인): 칭기즈 칸, 메흐메트, 엘레오노르, 엘리자베스, 프리드리히, 요리토모, 키루스 2세, 다리우스 1세, 아르테미시아, 알프 아르슬란 항목 10건. 좁은 곳은 short_name만 사용.
- short_name 5자 이상(권장 4자 초과, 번역 불가한 이름 그대로): 알렉산드로스, 힐데가르트, 아만니레나스, 아우렐리우스, 엘레오노르, 엘리자베스, 레오나르도, 프리드리히, 아르테미시아, 자랄 앗딘 10건.
- 중복: 완전 동일 title 0건. 다만 "고려 태조/조선 개국 태조", "술탄/칼리프" 같은 직함 어휘 겹침은 의도적이다(역사적 동일 직함).
- 기존 title은 거의 전부가 `~의` 로 끝나는 접두형이었으나 v2는 직함·저서·사건 명사형으로 바꿨다. '의' 글자를 포함한 title은 44건이지만 '의학/어의/의령' 같은 단어 속 글자를 포함한 수치이고, `~의 ○○` 패턴 자체는 그보다 적다(정확 집계는 하지 못함).
