# 전장 이벤트 서사 파일럿 설계 제안서 — ch12 적벽 (2026-11-07, 송서사)

상태: 설계 제안서. stages/dialogue 데이터·코드·DB는 수정하지 않았다. 수치(승률 영향)는 미측정이며 임밸런 재측정이 전제다. 신규 에셋 0(기존 초상·스프라이트·맵·효과음만: sfx_battle_charge / clash / gallop / roar / fire / water_rise).
원칙: 대사에는 사실/각색/근거 표기를 넣지 않는다(근거·확인 항목은 문서 끝 8절 내부 검수용). 본편은 주인공(전령)이 장수들과 함께 푼다. 시오리는 전투 중에 나오지 않는다.

## 0. 엔진 확인 결과 (app/Game/Cues.php, Engine.php, EventConditions.php 직접 확인)

| 질문 | 답 | 근거/제약 |
|---|---|---|
| 장수가 갑자기 죽는 연출? | 가능 | `retreat` + `"reason":"death"`: 유닛(+소속 병사) 제거, `defeated` 기록(= `defeated` 조건 참, `unit_survive` 서브목표 실패). 지휘관·주인공 불가(무동작). `must_survive` 유닛이 death 되면 즉시 패배(우회 불가) |
| 부상 후 퇴장/귀환? | 가능 | `retreat`(기본 reason=retreat)는 `retreated` 기록만 남고 `defeated`에 안 들어간다 -> 패배조건 `defeated`·`unit_survive`에 안 걸림. 귀환은 `spawn`(hero) 재소환으로 구현(HP/레벨은 새로 시작) |
| 전사 직전 HP 조정? | 없음 | hp 변경 cue 없음 -> "중상인데 안 죽음"은 연출 불가(퇴장으로 대체) |
| 이탈/투항 | 가능 | `defect` b->a(또는 a->b). 지휘관·주인공·`must_survive` 불가. 병사 동반 전환 |
| 증원 | 가능 | `spawn`(hero 또는 unit_type, count<=6, tiles<=12 후보, 빈 칸 없으면 조용히 skipped). 영웅 spawn 시 같은 인물을 플레이어가 출전시켰으면 생략됨 |
| 목표 문구 변경 | 없음 | win_conditions는 정적, HUD 문구 갱신 cue 없음 |
| 적 AI 지시(사격 보류 등) | 없음 | `set_ai` 류 없음 |

**함정 3개(설계에 반영함)**
1. 코드 불일치: ally_npcs 코드와 대사 화자 코드가 다르다(장비: 데이터 `zhang_fei`, 화자 `hero:npc_zhang_fei`). say/조건은 별칭이 통하지만 `retreat/defect/move`는 정확 일치(exact)라 `hero:npc_zhang_fei`로는 못 맞춘다 -> `hero:zhang_fei`를 써야 한다.
2. 플레이어 동일 영웅 충돌: `guan_yu`, `zhou_yu`, `liu_bei`, `zhang_fei`, `zhuge_liang`은 플레이어도 편성 가능한 코드라, `hero:zhou_yu`를 retreat/move하면 플레이어 영웅이 대상이 될 수 있다(npc_ 접두 코드만 별칭 차단). -> 엔진 작업 E1 전에는 이 코드들에 retreat/defect 금지(npc_ 코드와 무명 유닛만).
3. 화자 소멸: 퇴각/격파된 hero 화자의 say는 자동 생략. 퇴장 직전 대사는 retreat cue보다 앞(정의 순서)에 둔다. 한 번 발동한 cue는 재발동하지 않는다(조건 충족 첫 시점 1회).

## 1. 설계 규칙 (이 장 공통)

- 실존 인물 중 사료상 이 시기에 살아남은 사람은 전사 금지(부상·낙수·후퇴·패주로 표현). 전사 연출은 무명 장수 또는 사료상 사망한 경우로 한정한다. ch12 전 스테이지에서 전사 연출 0건이 정답이다(사료상 이 장의 주요 장수 사망 없음). 대신 "퇴장+귀환"과 "형주 병사 이탈"로 돌발성을 만든다.
- 지휘관(enemy_commander)이 된 실존 인물은 격파 시 "전사"가 아니라 "패주/철수"로 후일담을 쓴다(s1·s6 격파 전환 시 post 문구 점검).
- 증원/퇴장은 반드시 플레이어 행동(신호 구역 도달, 위기 HP)이나 예고된 사건의 결과로 일어난다. 무조건 구원 금지.
- 상태 변경 이벤트(spawn/retreat/defect/terrain/fire)는 스테이지당 최대 2개, 대사만 있는 연결형을 별도로 둔다(밸런스 비용 0).

## 2. 스테이지별 설계 (s1~s10)

범례: 트리거는 `on.turn`(최소 라운드) + `when`. 좌표는 기존 데이터에 있는 것만 기재, 나머지는 `<맵 확인>`(맵디자이너/임밸런이 적용 단계에서 채움).

### 표준 템플릿 (cue JSON 스켈레톤)
공통: `on` 안에 `turn`(최소 라운드)과 `when`(조건). 같은 트리거에 여러 cue를 같은 `on`으로 나열하면 정의 순서대로 연속 발동.

```json
// T1 아군 증원 도착
{ "on": {"turn": 3, "when": {"any": [
    {"type":"in_zone","unit":"@protagonist","tiles":[[19,13],[20,13]]},
    {"type":"turn_gte","value":5} ]}}, "do":"camera","mode":"focus","tile":[19,14],"ms":700 },
{ "on": { /* 동일 */ }, "do":"sfx","key":"sfx_battle_gallop" },
{ "on": { /* 동일 */ }, "do":"spawn","side":"a","hero":"guan_yu","tiles":[[18,13],[18,14],[18,15]],"tag":"guan_fleet","ready":true },
```

### 챕터당 권장 이벤트 수
- 챕터(10스테이지) 총 18~22개: 본 스테이지(비선택) 스테이지당 2개, 선택 스테이지 1~2개.
- 상태 변경 이벤트(T1/T2/T3/T4/T5) 스테이지당 <=1.5, 챕터당 총 10~12개. T6/T7(대사만)로 나머지.
- T1 챕터당 3~4, T2 3, T4 5~6, T5 3, T3 0~1(사료 허용 시).
- 한 이벤트의 대사는 3~6줄. 한 스테이지 전투 중 대사 총량은 12줄 이내(기존 battle_cues 포함).

### 반복 패턴 방지 규칙
1. 같은 유형을 연속 두 스테이지 주 이벤트로 쓰지 않는다(예: s3 낙수 다음에 s4는 철수형).
2. 트리거 종류 순환: in_zone -> hp_pct -> turn -> flag -> defeated/retreated.
3. 증원은 "플레이어 행동의 대가" 또는 "예고된 위기의 해소"만. "마지막 순간에 영웅 도착"은 챕터당 1회.
4. 같은 인물의 같은 반응 반복 금지(감녕 외침 챕터당 2회, 조인 "명령 확인" 챕터당 2회).
5. 모든 이벤트에 새 정보·관계 변화·선택 중 최소 1개. 삭제해도 같으면 제거.
6. 목표 문구와 충돌 금지: 승리 조건이 격파로 바뀐 스테이지에서는 "지켜라/호위하라" 대사 금지.
7. 전사 연출 전 체크리스트: ① 사료상 사망한 인물인가 ② must_survive 아님 ③ lose/sub_objective의 `defeated` 영향 ④ 후속 반응 cue 있음.
8. 사료상 생존자가 지휘관이 되어 격파되면 후일담은 "패주/철수"로 쓴다.

## 4. 퇴고 요약 (편집자 모드)

## 5. 박백엔에게 필요한 엔진 작업 (우선순위)
- E1 (필수) 유닛 참조에 아군 NPC 한정 필터(예: `npc:zhou_yu` 또는 cue `npc_only:true`): retreat/defect/move/camera가 플레이어 동일 영웅을 건드리지 않도록. 이 전까지 zhou_yu/guan_yu/liu_bei/zhang_fei/zhuge_liang에는 상태 변경 cue 금지(say·spawn만).

## 9. 사용자 결정 필요 (5개)
1. 실존 인물 "전사" 원칙 승인: 사료상 생존자는 부상·낙수·후퇴로 대체, 전사는 무명 장수·사료상 사망자만. (ch12는 전사 0건이 됨)
2. 격파 전환 스테이지(s1·s6)의 지휘관 후일담을 "패주/철수"로 통일하고, s1에 유비 생존 패배조건을 둘지.
3. 선택 스테이지(s5~s10)에도 본 스테이지와 같은 밀도(1~2개)로 넣을지, 본 스테이지(s1~s4) 위주로 할지.
4. 증원 균형 방식: 아군 증원 1기당 적 증원 또는 enemy_level_offset 보정 중 무엇을 우선할지, 임밸런 재측정 허용.
5. 엔진 작업 E1(필수) 외 E2/E3/E5(선택) 착수 여부와, s7·s9 주유/s10 손권의 ally_npcs 추가 허용.

## 부록: ally_npcs 시작 칸 vs 실화면 위치 (2026-11-07 조사, 오류 아님)

- DB·시드 값은 설계와 일치: s7·s9 주유 (3,13), s10 손권 (3,14). 맵 931/935/936 의 해당 칸은 모두 평지(통행 가능), 시작 칸 보정(ArmyBuilder::addAllyNpcs 의 가까운 빈 칸 탐색)은 점유·통행불가일 때만 동작하며 여기선 발동하지 않는다.
- 실화면 위치(주유 (5,13), 손권 (3,17))는 전투 개시 직후 선공(아군) 단계에서 BattleService::allyPhase 가 NPC 봇을 먼저 구동해 이동시킨 결과다(battle_actions 로그: 턴1 `move n1 -> (5,13)` / `(3,17)`, npc_ally). 즉 (3,13)/(3,14)는 "시작 칸", 플레이어가 처음 보는 칸은 봇 이동 후 칸이다.
- 고정하려면 별도 엔진 옵션(NPC 대기/hold)이 필요하다. 현재는 의도된 동작이므로 변경하지 않음.
