## 2. 배너 구조와 v1 대조 (사실: stages.chapter 와 데이터 파일)

## 4. 분석과 조정안 (사실/산술/가설 구분)

1. [산술] 영웅 1명 균등 확률 = 등급 확률 / 배너 내 같은 등급 인원. 배너 S1/A3/B8/C8 이면 S 2.0%, A 3.3%, B 3.75%, C 7.25% (전체 풀의 14~23배). 풀 20명이 4% 크기라 "목표 영웅을 뽑는" 속도는 매우 빠르다.
2. [시뮬레이션] 천장 x20 부스트는 작은 풀에서 지나치게 강하다. 같은 배너에서 부스트 배수별 필수 전원 평균(단발 4000회):

| 배너(필수 수) | x1(K만) | x3 | x5 | x10 | x20(현행) |
|---|---|---|---|---|---|
| ch1 임진(6, 풀 43 = 적측 포함) | 88.7 / p90 124 | - | 67.5 / 93 | - | 46.7 / 65 |
| ch21 레그니차(5, 풀 26) | 50.1 / 72 | - | 39.0 / 60 | - | 33.3 / 52 |
| ch12 천하삼분(7) | 66.6 / 93 | 59.2 / 84 | 54.8 / 78 | 51.0 / 73 | 48.3 / 71 |
| ch18 몽골(3) | 54.5 / 74 | 52.5 / 70 | 51.8 / 68 | 51.1 / 67 | 50.8 / 66 |
| ch23 헤이스팅스(1 B) | 18.2 / 31 | 10.5 / 25 | 7.8 / 18 | 5.7 / 12 | 4.5 / 10 |

   ch23 처럼 필수 1명뿐인 챕터는 평균 4.5회로 사실상 "10연 한 번이면 보장"이 되어 뽑기 긴장감이 사라진다(가설). 반면 ch12·ch18 처럼 S 필수가 낀 챕터는 부스트 영향이 작고 K=30 이 상한을 정한다. 권고: 배너 풀에서는 부스트를 x5 로 낮추거나(ch23 평균 7.8, ch1 38.4) 배너 안에서는 부스트 없이 K 천장만 쓰는 안(ch23 18.2, ch1 51.2). 이는 엔진 파라미터(config game.gacha.required_boost, env GAME_GACHA_REQUIRED_BOOST)이므로 박백엔에게 요청 항목이다(자세한 건 5장).
3. [사실] 권고 기준 "필수 1명 평균 30~60회": 부스트 없는 균등 기준 배너 기대값은 B 27, A 30, C 14, S 50(1 S) 로 대부분 대역에 들어온다. 풀 크기를 이보다 작게(B<=5) 하면 B 필수가 20회 이하로 떨어져 가치가 무너지고, 크게(B>=15) 하면 B 균등이 50회를 넘어 천장 의존이 커진다. 시작값 B8 은 대역 하단~중간이다. C 인원 8 은 C 필수 14회로 짧으니 C 를 12~16 으로 늘리면 25~30 회(조정 후보).
4. [사실] S 비중: 배너 S 인원은 1~2, 확률 2%. S 필수(이순신, 관우, 잔 다르크, 알렉산드로스, 칭기즈 칸, 살라딘)는 배너 안에서 균등 50회(S 1명) / 100회(S 2명, ch18·ch19), 천장 병행 약 23~24회. 확률 2% 가 고정이라 S 2명 배너(ch18, ch19)의 균등 100회는 챕터 진행 대비 무겁다 -> 천장이 사실상 필수 장치다(K=30 으로 상한 31회). S 필수가 몰린 ch18(칭기즈·제베·수베에데이)는 MC 평균 50.8회로 가장 무거운 편(ch12 48.2, ch1 33.0). 두 챕터에 A·B 부스트 감소 안을 적용하면 ch18 은 부스트 영향이 작아 변화 없음.
5. [가설] 서고(전체 풀)는 천장 없이는 B 필수 1명 약 710회(약 7만 골드)라 필수 영웅을 모으는 경로가 아니다. 서고는 "배너에 없는 영웅 수집 + 중복 조각" 역할이고, 필수 영웅 천장은 서고에서도 동작한다(대상이 서고 풀에 있음) -> 최악 31회가 서고에서도 보장되므로 배너 선택 실수(다른 시나리오 배너에서 뽑음)에는 필수 천장이 적용되지 않는다(대상이 그 배너 풀에 없으면 카운트되지 않음). UI 에서 "이 배너는 현재 막힌 스테이지의 영웅이 포함되어 있다" 표시가 필요하다.
6. 하한 조정: 문기획 S1/A2/B3/C3 은 풀이 9명이라 필수 B 1명이 3명 중 1명 -> 균등 약 10회 이하로 너무 쉽다. S1/A3/B8/C8(20명) 으로 상향했고 사람 플레이 피드백이 필요하다. 크기 상한 50%(251)는 전혀 닿지 않는다(최대 27).

## 6. 시나리오 레지스트리 파생 구조 제안 (신규 시나리오 -> 배너 자동 생성)

배너 정의를 수동 목록이 아니라 시나리오 레지스트리에서 파생한다. 제안 파일 `database/data/scenario_registry.json`(엔진 코드 변경 아님, 박백엔 구현 필요).

| 필드 | 필수 | 설명 |
|---|---|---|
| key | 예 | `sc_ch26` 등 시나리오 고유 키(= 배너 key) |
| chapter | 예 | stages.chapter 값. 스테이지 코드 접두(chN_s*) 로 필수 영웅 수집 |
| title / sub | 예 | 배너 제목/부제 |
| art_key | 아니오 | 일러스트 별칭. 없으면 기본 배경 폴백 |
| year | 아니오 | 풀 보충 시 기준 연도(heroes.born 근접순). 없으면 해시 회전 |
| cultures | 아니오 | 보충 문화권 목록(heroes.culture) |
| appearance_files | 아니오 | 등장 인물 추출 대상 대사/스테이지 데이터 파일 |
| include / exclude | 아니오 | 수동 보정(풀 영웅 코드) |
| min_counts | 아니오 | 등급 하한(기본 S1/A3/B8/C8) |

생성 절차: `php artisan game:gen-scenario-banners`(제안 명칭) -> (1) stage_required_heroes.json 에서 chapter 접두 스테이지의 필수 영웅 수집(+required_when_obtainable) (2) appearance_files 등장 코드 중 풀 영웅 추가 (3) 등급 하한 보충(문화권, 출생연도 근접, 부족 시 타 문화권 표시) (4) exclude/include 반영 (5) `gacha_banners.json`(생성본) 쓰기, 결정적(같은 입력 -> 같은 출력, 날짜 독립) 이라 재실행 안전.
감사(audit, `game:audit-stages` 확장): (a) stages 에 존재하는 모든 chapter 가 레지스트리에 있고(튜토리얼·종장 예외 목록 명시) 배너가 있다. (b) 각 배너 pool 이 해당 chapter 필수 영웅 전원을 포함(미편입이면 pending 목록에 없는 한 실패). (c) 등급 하한 충족과 크기 < 전체 풀 50%. (d) pool_codes 가 모두 현재 풀에 존재. (e) art_key 에셋 존재(없으면 경고).

### 예시: 카이사르 루비콘 (art_key = europe)

레지스트리에 `key=sc_rubicon, title=카이사르 루비콘, art_key=europe, year=-49, cultures=[ancient_med, europe], required=[julius_caesar]` 만 등록하면 풀 20명(S1/A3/B8/C8)이 자동 생성된다. 필수 영웅이 확정되고 appearance_files 가 생기면 등장 인물이 앞쪽으로 들어오고 보충분이 줄어든다. 현재는 로마·고대 지중해 인물이 부족해 중세 유럽 인물이 연도순으로 일부 섞여 있어(보충분 마르쿠스 아우렐리우스, 스키피오 아프리카누스, 파비우스 막시무스, 아르키메데스, 아르테미시아 1세, 레오니다스 ...), 로마 인물 영웅 추가 또는 cultures 정정이 필요하다(제안 사례일 뿐). 삭제되는 europe(대륙의 패권) 배너의 일러스트(gacha.title.europe/.native, tint 0x1f3a8a, 카이사르 대표)를 이 배너가 art_key=europe 로 재사용한다.

## 10. 적군 영웅 포함 규칙과 시나리오별 적측 영웅 (사용자 확정 반영)

- 추첨 풀 = 아군 + 적군 전체. 적측 영웅은 필수가 아니므로 소프트 천장 대상이 아니고 일반 풀 구성원이다(확률은 등급 확률 / 배너 내 같은 등급 인원).
- 뽑기 화면 노출(쇼케이스·이름표·대표 표시)은 아군 영웅만. JSON 의 각 배너에 `pool_codes[].side`(ally/enemy/unspecified)와 `showcase_codes`(아군 확정자 최대 5명, 등급 높은 순, 필수 우선)를 넣었다. unspecified = 대사 화자만 등장했거나 양측 같은 문화권이라 편 판정이 불가한 인물(송서사 확정 필요).
- 적 판정 근거: DB stages.enemy_squad 의 지휘관 npc_ref(kind≠generic) + rules.enemy_commander.hero. 직함형·무명 적(적장, 척후, 선봉장, 수비대장, 먹그림자 등)은 정규식(captain/chief/commander/vanguard/scout/guard/shadow/garrison/patrol 등)으로 제외했다. ch101~104 의 서민·메타 NPC(의도적 획득 불가)와 동명 중복 npc_yu_bang 도 제외.
- 레지스트리 규칙: `appearance_sources` 에 `stage_allies`, `stage_enemies`, `stage_speakers`, `dialogue_files` 를 두고 `include_enemies: true`(기본). 생성기는 stages.enemy_squad 를 읽어 적 지휘관을 side=enemy 로 추가한다. 쇼케이스·대표 표시는 side=ally 만 사용.
