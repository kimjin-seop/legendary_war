# 맵 프리셋 20종 설계서 (maps_pack20.json)

작성: 임밸런. 모든 수치는 시작값(가정 포함). 최종 느낌·밸런스는 사람 플레이 피드백과 최종 밸런스 단계 재측정 필요.
재생성: `python docker/maps/gen_pack20.py <프로젝트루트> [--ascii]` (결정적, 난수 없음) / 검증: `docker compose exec -T app php docker/maps/check_pack20.php` (읽기 전용).

## 1. 현황(코드에서 읽은 사실)
- `maps.json`: 항목 {code,name,biome,rules,tiles(행 문자열),spawns{a,b}(6칸, 첫 칸=지휘관),deploy_zones{a,b}}. 크기는 tiles에서 산출. 기존 9종(16x12 / 10x8 / 20x14 ×5 / 24x16 ×2)은 모두 좌우 3열 배치 영역(42~48칸).
- GameSeed는 `maps.json`만 읽고 `code,name,tiles,spawns,deploy_zones,biome,rules`만 저장. `meta` 같은 추가 키는 무시됨(저장 컬럼 없음).
- 방 생성: `config('game.room_map_codes')` 8종 허용 목록 + `random`(solo). FE 로비 `createRoom()`은 `gameApi.rooms.create(mode, visibility)`만 보내며 **맵 선택 UI가 없음**(API는 map_code 지원).
- 스테이지는 `stages.json`의 `map`(code)을 시드가 `map_id`로 변환. 즉 새 맵이 `maps`에 들어가면 스테이지는 code만 바꾸면 재사용 가능.
- MapChecker 검사: 지형 문자·크기, 배치 영역 통행·겹침, 스폰, 지휘관 간 도달·접근비용 비대칭(25%), 지형 비율(평지 30~85%, 단일 지형 ≤50%, 보병 불가 ≤35%), 고립 영역. `game:map-check`는 DB 대상이라 신규 파일은 `docker/maps/check_pack20.php`로 같은 클래스를 사용해 검증.
- 엔진 제약(campaign_ch1_outline 기준): 목표 2종(commander_defeat / survive_turns), 맵 문자 지형은 terrains.json 13종 전부 사용 가능(outline의 5종 제한은 구버전 기록, 현재 코드 값 기준).
- 렌더 규칙(FE 코드): 프리팹 숲 3x2/2x2/2x1/1x2, 산 2x1/1x2(4칸 이상은 절벽 오토타일 고원), 성 2x2/1x2/2x1, 마을 2x2/2x1, 다리는 가로/세로 중 긴 구간, 폭 2칸 이상이면 넓은 다리. `snow_desert`는 biome이 `desert`가 아니면 **설원 렌더**(그래서 사막 맵만 biome=desert, 설원 맵은 `snow`, 그 외 맵은 `n` 미사용).
- 이동 비용(terrains.json): 숲 보2·기3·중2 방어+20, 산 보3·기·중 불가 방어+30(고지), 여울 2(-10), 늪 보3·기·중 불가(-10), 설원·사막 2, 절벽·성벽 불가(비행만 절벽 가능), 성 방어+30, 마을 방어+10·회복, 다리·도로 1.

## 2. 설계 원칙
1. 모든 지형 편집은 대칭 이미지와 동시 적용(점/좌우/4중). PvP 맵은 타일·배치영역·스폰이 변환 후 100% 일치(생성기가 검증). `second_atk_pct` 미사용, `rules` 비움(전역값 사용).
2. 지형은 단독 1칸 금지(비평지 모든 칸이 같은 지형 이웃 보유), 숲·산·성·마을 군집은 2x2 중심, 다리는 직사각형·폭 1~2·길이 ≥2·양 끝 통행 가능(생성기 검증).
3. 배치 영역은 양 끝 3열 × 전체 높이(S 36 / M 48 / L 60칸 ≥ 영웅6+부대 4×6=30칸), 스폰은 기존 방식(지휘관 후열, 6칸). 영웅 스폰별 반경3 내 빈 배치칸 ≥9(비대칭 맵 15).
4. 병목은 '비용'이 아니라 '통행 불가'(물·절벽·성벽·산=기/중 불가)로 만들어 이동력이 커져도 유지(산 고개: 기병 min-cut 2, 중장갑 2).
5. 접촉 라운드: 존 간 최소 진입비용 합 gap에서 `ceil((gap-1-이동력)/(2×이동력))+1`(양측 전진·사거리1 가정, 봇·사람 행동 미반영).

## 4. 스폰 간 접촉 해석
- 현행 이동력에서 S=2R, M=3R, L=4R(보병) → 6v6 대형은 첫 접촉이 늦음. 중장갑은 +1~2R. 이동력 2배 시 M=2R, L=2~3R로 줄지만 병목 맵(02·10·14·20·11·06·18)은 통행 불가 지형 때문에 cut이 유지됨.
- 병목 지표가 큰 열린 맵(01·04·05·13·15·17)은 의도적으로 측면 기동형. 이동력 2배 도입 시 병목은 얇아지지 않으나 열린 맵은 접촉이 빨라짐(재측정 필요).

## 6. 통합 제안(구현은 박백엔·윤프론)
1. 적재: GameSeed가 `maps.json` 외에 `maps_pack20.json`의 `items`도 병합(같은 스키마라 `put('maps', …)` 재사용, code 기준 idempotent). `maps` 테이블에 신규 컬럼 `meta` (JSON, nullable) 마이그레이션 1건 추가해 `meta.theme/size_class/pvp_fair/pvp_listing/recommended_per_side/tags/biome_tag/difficulty_hint/campaign` 저장(미저장 시 JSON을 서버가 직접 읽는 대안은 배포 파일 의존이라 비권장). 운영 DB는 마이그레이션 백업·롤백 계획 필요.
2. 허용 목록: `config game.room_map_codes`를 하드코딩 대신 `meta.pvp_listing`·`campaign_ok` 기반으로 산출. PvP는 `pvp_fair && pvp_listing==='default'`만, solo는 비대칭 맵 포함 가능(설원 맵은 렌더 검증 전 보류).
3. API: `GET /api/maps?mode=solo|pvp&per_side=N&biome=…` → `[{code,name,width,height,theme,size_class,biome_tag,recommended_per_side,tags,pvp_fair,difficulty_hint,preview:{tiles}}]`. 미리보기는 tiles 문자열 그대로 내려주면 FE가 색 격자로 렌더(무료·가벼움). `POST /api/rooms`의 `map_code` 검증은 서버가 목록으로 판단, PvP에서 비대칭 맵 422.
4. FE(Lobby `createRoom`): 모달에 맵 선택 추가(크기 클래스 필터, 이름·크기·테마·태그·추천 인원, 미니맵, 랜덤 버튼=solo 전용 또는 PvP는 공정 맵 중 서버 추첨). 방 대기실에 선택 맵 표시.
5. 캠페인: `stages.json`의 `map`에 `pk_*` code 지정만으로 연결. 후속 후보: 적 매복 구역(`enemy_extra_zones`), 점령 목표(마을/성), 방어 대상 지정은 엔진 변경 요청 사항(별도).
6. 6v6 한도: `max_units_per_side` 코드 clamp가 16(`min(16,…)`)이라 영웅 6+부대 시 유닛 상한 재설계 필요(박백엔). 배치 영역은 이미 30칸 이상 확보.

## 7. 리스크·확인 필요
- 28x20(560칸) 렌더·성능은 **미확인**(현재 최대 24x16). RM 지형 합성 캔버스 1344x960 px 수준이라 이론상 가능하나 FE 실측(강화면) 필요. 줌 하한·카메라 스크롤도 확인.
- 설원 맵(pk_08)은 설원 바이옴 렌더 미검증 → `pvp_listing=hold`, `campaign_ok=false`.
- 프리팹 적합성: 숲 3x2·2x2 위주, 산 2x2 이상(4칸 이상은 고원 렌더), 성 2x2/1x2/2x1, 마을 2x2, 다리 폭 2. 실제 화면 검증 미실시. pk_11 능선(2x6 3줄)·pk_17 능선(18x2)·pk_03 능선(8x2)은 고원 오토타일 렌더가 '빈 상자'로 보이지 않는지 확인 필요.
- 접촉 라운드는 계산값. 봇의 접촉 회피 성향(6v6 turn_limit 78% 측정 참고)은 실제 시뮬 미실시(이번 작업은 맵 설계 중심, 시뮬 0회).
- 양 진영 대칭이어도 선후공·고지 효과는 별도 측정 필요(교대 행동 on 후 맵별 선공 승률 5%p 이내 확인 — 최종 밸런스 단계).
- 이름은 일반 명칭, 역사 단정 없음. ch1 매핑은 outline의 evidence_level 따름.

## 8. 팀장 결정 반영(위임 결정 4건)
1. 6v6 기본 맵은 24x16 중심. 28x20(5종)은 FE 성능 실측 후 공개.
2. 설원 `pk_08` 보류 유지(`pvp_listing=hold`). 비대칭 2종(`pk_06`, `pk_18`)은 solo 전용, PvP 제외.
3. PvP 맵 지정은 방장 지정 + 랜덤 옵션(투표는 2차). 랜덤은 `pvp_fair && pvp_listing=default` 중에서 서버 추첨.
4. `maps.meta` JSON 컬럼 마이그레이션 승인(박백엔 구현). `decor`와 `village_style`도 시드가 읽어 저장해야 함(현재 시드는 무시).

## 9. decor(장식 전용 비판정 레이어)와 프리팹 맞춤
- 스키마: 맵 항목의 선택 필드 `decor:[{prefab,x,y,flip?}]`(x,y=발자국 왼쪽 위 칸). 선택 필드 `village_style:"town"|"camp"`(맵 단위, 없으면 군집마다 해시).
- 사용 프리팹(윤프론 확정 목록 중 decor 전용만): statue1x2·statueMage1x2·statueDragon2x2·obelisk1x2·colonnade3x1·altar2x1(이상 large), bannerRow1x2·lanterns1x2(low). monument4x2는 2행 높이라 가장자리 배치 불가해 이번에는 미사용.
- 검증 규칙: large는 산·절벽·성벽·물 칸 또는 맵 가장자리 칸에만, low는 어디든 가능. 모든 decor는 배치영역·스폰에서 맨해튼 2칸 이상. large끼리 겹침 금지. 대칭 맵은 장식도 같은 변환(좌우 이미지는 flip 토글)이고 발자국 대칭을 검증(생성기 `check_decor`). 병목 통로 가독성은 코드로 강제하지 않음 -> 실화면 확인 필요.
- 구성: 호수·강·해협의 물 칸에 statueDragon·obelisk(pk_07 오아시스 중앙, pk_10, pk_14, pk_19, pk_20), 절벽·능선에 statue/statueMage/obelisk(pk_03, pk_11, pk_16, pk_17), 성벽·해자(pk_18), 가장자리 colonnade/altar(대부분 중형·대형), 길목 low bannerRow/lanterns. 숲 맵(pk_05, pk_17)의 거목 군집은 장식이 아니라 숲 군집 크기(2x2·2x3)로 표현해 FE가 giant/giantGrove를 선택하게 함.
- village_style: pk_15 `camp`(군영 점령전, 마을 2x2 -> tent2x2), pk_07 `camp`(사막은 천막 야영지가 맵 성격에 맞음), pk_13·pk_04·pk_12·pk_06·pk_18 `town`. 나머지는 지정 없음.
- 지형 군집 조정(프리팹 맞춤): pk_12 중앙 성 군집을 4x4(keep4x4)로, pk_18 주 성채 4x4, pk_04·pk_13 중앙 마을 4x2(market4x2 후보), pk_12 외곽 마을 3x3(mansion3x3 후보). 큰 산 군집 최소화: 2x2 산을 2x1/1x2 능선으로 바꿈, pk_11은 2x6 능선 3줄+절벽, pk_03 산은 8x2 능선+절벽 줄, pk_17 능선(18x2)은 길어서 고원 오토타일 렌더 확인 필요.
- 미확인: 프리팹 실화면 미리보기(윤프론/강화면), decor가 병목·성문 가독성에 미치는 영향, 설원 맵 장식.
