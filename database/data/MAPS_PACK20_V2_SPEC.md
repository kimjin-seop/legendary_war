# 맵 프리셋 v2 설계서 (maps_pack20_v2.json)

작성: 임밸런. 모든 판단은 가정이며 수치는 계산값(시뮬레이션 0회). 재생성: `python docker/maps/gen_pack20_v2.py <루트>`, 검증: `docker compose exec -T app php docker/maps/check_pack20.php`(v2 파일은 인자 `maps_pack20_v2.json`). 건물 프리팹 크기는 `docker/maps/v2_prefab_params.json`.

## 1. 설계 원칙(일반 원칙 + 레퍼런스 이미지 관찰)
레퍼런스 스크린샷은 레이아웃·원칙 참고용이며 어떤 맵도 복제하지 않았다.

| # | 원칙 | 적용 방식 |
|---|---|---|
| 1 | 자연스러운 대륙 형태: 불규칙 해안선·하천 굴곡·넓은 평지+부분 고지, 하천이 지형을 가르고 다리 1~2개로만 건넘 | 자연형 맵은 사인 노이즈 해안·하천 곡선으로 생성(결정적). 직선 사각 군집 지양 |
| 2 | 숲은 띠·군집으로 한쪽에 몰려 엄폐·시야 장벽 | 노이즈 임계 숲 띠(여러 줄 군집), 후열 엄폐 지대 |
| 3 | 대형 건물군(3~4칸)이 거점·엄폐·장애물, 건물 사이 통로 | `v2_prefab_params.json`의 저택 3x3·회관 3x2·시장 4x2·성 4x4를 서버 지형 코드(마을=v 이동 가능, 성=c, 성벽=W 이동 불가)로 배치, 사이는 평지 |
| 4 | 도로가 거점·다리·목표를 연결, 다리가 병목 | 경로 탐색(가중 BFS)으로 도로를 깔아 다리 양 끝과 거점을 연결 |
| 5 | 점령 목표(깃발)가 맵 끝에 여러 개 분산 | 자연형 맵 `meta.objective_points`(후보 좌표, 현재 엔진 미지원) |
| 6 | 부대 단위 초기 배치가 지형 구획별로 나뉘고 비대칭(아군 한쪽 집중, 적 분산) | 자연형 맵은 비대칭 배치 구역, 적 추가 포켓(`enemy_extra_zones`) |
| 7 | 수상/비행 유닛이 해역에 별도 배치 | `meta.naval_zone` 후보(수병 v2 이동 규칙은 코드 확인 필요), 수상 비중 확대 맵 |
| 8 | 맵 가장자리 프레임 + 큰 연속 지형 | 자연형 3종은 28x20, 가장자리 장식은 decor/FE 프레임 |

일반 SRPG 설계 원칙(공통): 병목과 측면 우회로 공존, 고지·엄폐 거점, 회복 마을·보급 거점, 점령 목표, 다리·여울 선택 비용, 비대칭 초기 위치, 전열-후열 공간, 거점 간 거리와 접촉 라운드, 한눈에 이해되는 지형 군집 형태, 병종 상성이 지형에서 갈림(기병=평지 우세·숲/산 불리, 궁병=고지, 창병=병목, 수병=물, 암살자=측후방 루트, 마법사=후열 엄폐).

**공정성 정책(제안)**: PvP는 점/좌우/4중 대칭 유지, 자연형·비대칭은 solo/캠페인 전용(`pvp_listing=excluded`). v2에서 자연형 비중 20종 중 3종(15%) -> v2.1 후보(pk_09·16·18) 포함 시 30%.

## 5. 맵별 전략 메모(한 줄)
- `pk_01_plain_clash` 벌판의 대치 유지: 입문용 평원, 중앙 능선 2칸을 사이에 둔 측면 기동 학습.
- `pk_02_ford_small` 나루터 도하 개편: 강폭 2->4, 다리 길이 4로 수상 비중 약 27%, 다리 1+여울 2개 병목, 숲 엄폐는 본진 앞.
- `pk_03_narrow_gorge` 좁은 협곡 어귀 유지: 기병 병목(cut 4)과 능선 고지 사격, 보병만 능선 우회.
- `pk_04_hill_claim` 구릉 선점전 개편: 중앙 4x2 마을을 절벽 두 줄이 낀 4칸 폭 통로가 감싸는 거점, 후방 회복 마을 2, 숲 엄폐 2군집.
- `pk_05_forest_ambush` 숲속 매복 유지: 숲 군집 매복(2x3/2x2), 중앙 마을 회복.
- `pk_07_oasis` 오아시스 쟁탈 유지: 모래 감속 + 중앙 오아시스 쟁탈(camp 양식).
- `pk_08_snow_ridge` 설원 능선 유지(보류): 설원 렌더 검증 후 사용.
- `pk_09_swamp_detour` 늪지 우회로 유지: 늪 중앙 여울 지름길 vs 외곽 도로 우회, 기병 불가 늪(자연형 전환은 v2.1 후보).
- `pk_11_mountain_pass` 산악 고개 유지: 고개 한 줄(기병 cut 2) + 능선 고지, 중앙 마을.
- `pk_13_crossroads` 십자 교차로 유지: 십자 도로와 중앙 4x2 마을(market 후보).
- `pk_15_village_war` 마을 점령전 자연형 전환(비대칭, solo/캠페인, 24x16->28x20): 하천 곡선+다리 2·여울 1, 군영 6+2 거점, 우측 점령 거점 분산, 숲 띠 4.
- `pk_16_cliff_valley` 절벽 계곡 유지: 절벽 능선 사이 계곡, 능선 위 사격(자연형 전환은 v2.1 후보).
- `pk_19_lake_loop` 호수 순환로 개편: 호수 8x10, 중앙 다리 10칸(길이 길어 노출), 외곽 여울 순환로로 수상 비중 약 35%.
- `pk_10_coast_isles` 해안과 섬 자연형 전환(비대칭, solo/캠페인): 불규칙 해안과 하천 곡선, 다리 1·여울 1, 좌측 건물군(저택 3x3·회관·시장·성), 우측 점령 거점 4곳, 수병 해역 구역.
- `pk_12_central_keep` 중앙 요새 쟁탈 유지: 중앙 성 4x4 + 4성문 쟁탈, 외곽 3x3 마을.
- `pk_14_twin_rivers` 두 강 사이 개편: 강폭 2->3으로 수상 비중 약 20%, 다리 4+여울 2, 가운데 땅에 마을 4x2.
- `pk_17_three_lanes` 세 갈래 길 유지: 북 도로/중 숲/남 늪 3차선, 중앙 연결 통로.
- `pk_20_grand_mixed` 대평원 대전 개편: 강폭 2->4, 다리 4칸 길이, 성 포스트·마을 좌우.
- `pk_06_fortress_siege` 성채 방어전 자연형 전환(비대칭, 24x16->28x20): 성문 1+쪽문 1, 성 안 4x4 본관+탑, 강 해자, 구릉 사격 지점, 적 2방향 포켓.
- `pk_18_wall_breach` 성벽 돌파전 유지(비대칭): 해자+2성문 돌파, 타일 건물 4x4 성채 적용은 v2.1 후보.

## 5b. tile_layer(시각용 타일 인덱스 레이어, 유니티 가이드 방식)
- 서버 판정은 `tiles` 문자열 그대로. 항목의 선택 필드 `tile_layer`={format:"names-v1", names[논리명], rows["i i i ..."(칸당 names 인덱스)], index_map}. 레이어가 없으면 FE는 지형 코드 단일 타일로 폴백.
- 생성기가 오프라인으로 칸마다 타일을 "칠함": 물가는 N·E·S·W 이웃 마스크(`grass_shore_NE`, `water_edge_S`), 숲·산·절벽 가장자리(`forest_0_NE`, `cliff_S`), 도로 연결(`road_NS`), 다리 방향·시작/중간/끝·폭 가장자리(`bridge_h_S_edge1`), 건물 칸 위치(`bld_v_3x3_1_0`, `bld_c_4x4_i_j`), 성벽 연결(`wall_ES`), 성문(`gate_i`). 맵 밖 이웃은 같은 종류로 간주(가장자리 이음새 방지). FE는 런타임 이웃 판정 없이 인덱스만 그린다.
- 논리명 -> 인덱스: `tileset_ext_spec.json`(ext_tiles 이름→전역 인덱스, 74종 30~103)과 원본 30칸 별칭(`ORIG_NAMES`)으로 `docker/maps/v2_tilemap.json`을 자동 생성해 `index_map`을 채운다(`--tilemap <매핑.json>`으로 대체 가능). 미매핑 이름은 `unmapped`에 기록하며 0이어야 한다. 시트 밖 인덱스(104 이상)는 검증에서 오류. 가로 다리는 `rotations.plank_h=1`(90도), 점령 깃발은 `overlay`(103).
- 정합 검증(`check_tile_layer`, 생성기 내장): 모든 칸의 타일 계열이 서버 지형 기호와 일치(grass=p, road=r, water=w, shallows=s, bridge=b, forest=f, mountain=m, cliff=k, wall=W, castle/gate/bld_c=c, village/bld_v=v, swamp=x, sand/snow=n)하고, 이동 불가(w·k·W)는 물/절벽/벽 계열일 때만 허용. 20종 모두 오류 0. MapChecker(PHP) 이식은 박백엔 선택(권장: 시드 시 경고).

## 6. 요구사항
**박백엔**: 시드가 `tile_layer`(+`meta`·`village_style`·`decor`)를 `maps.meta`에 저장하고 맵 응답에 전달. `maps_pack20_v2.json` 적재(`game:seed-maps-pack` 명령이 존재하는지 확인 필요, 없으면 GameSeed `packItems()`가 읽는 파일명을 v2로 교체하거나 병합 옵션 추가). 반드시 개발 DB 백업 후 적용, 기존 진행 중 전투는 map_id 불일치 위험(새 전투로). 크기 변경(24x16->28x20)된 pk_06·pk_15·pk_10 스테이지·방 호환 확인. `meta.objective_points`·`naval_zone`·`enemy_extra_zones`는 현재 엔진 미지원(목표/수병 구역 확장 시 사용). 병종 v2(수병) 이동 규칙(물 비용)은 `unit_types.json`에 아직 반영 전이라 이 맵의 수상 비중 효과는 가정.

**윤프론**: 자연형 맵 렌더 확인(불규칙 해안·하천 곡선에서 오토타일/unity32 지형 경계), 건물 프리팹이 `village`·`castle` 군집 크기(3x3, 4x2, 4x4)에 맞게 선택되는지, 큰 맵(28x20) 성능·미리보기, 가장자리 프레임, `decor`(large는 물·절벽·성벽·산·가장자리). 28x20 맵 수: v1 6종(10·12·14·17·18·20) + v2 신규 2종(06·15) = 8종(10은 자연형 전환으로 유지), 대형 상한 권고 8종.

## 7. 리스크·가정
- 접촉 라운드·cut·수상 비중은 계산값(봇/사람 행동·수병 규칙 미반영). 선후공 편향·승률은 최종 밸런스 단계에서 측정.
- 자연형 맵은 노이즈 생성+정리라 일부 칸이 의도와 다를 수 있음 -> 윤프론 화면 검증과 사람 눈으로 확인 필요.
- 건물 칸 수는 `v2_prefab_params.json` 가정값(3x3·4x2·4x4). 윤프론 보고와 다르면 파일 갱신 후 재생성.
- 점령 목표·수병 구역은 엔진 미지원(메타 후보). 현재 승패는 지휘관 격파.
