# 영웅 스킬 현황 조사 및 "전부 만든다" 견적 (2026-11-07, 임밸런)

조사 전용. 기존 코드/데이터/DB는 수정하지 않음(읽기 쿼리, `game:audit-skills` 읽기 전용만 실행). 수치는 시작값/미측정.

## 1. 현황 (사실: DB 직접 조회, 개발 DB)

- heroes 622행 = 가챠/수집형 202(campaign_only=0) + 캠페인 NPC 410 + 주인공 10. 스킬 계열 원본: skills 569행(active 198 / passive 371), hero_skills 695링크, 연결된 영웅 220명.
- skills 비활성(enabled=0) 9개: empty_fort(DECOY, 엔진 미구현), 패시브 8(T_PURSUIT 3 / T_MOVE_UP 3 / T_REGEN 1 등 구버전). 이 9개는 어느 영웅에도 연결되어 있지 않음(영향 0). review_status(pending_review)는 DB 전체 NULL = 보류 상태 없음.

## 2. 엔진 지원 현황 (사실: 코드 확인)

- 패시브 지원(PassiveEffects::SUPPORTED_TEMPLATES 18종): ATK_UP, DEF_UP, ATKDEF_HYBRID, HEAL_UP, TERRAIN_ATK, TERRAIN_DEF, VS_TYPE_ATK, LAST_STAND, COUNTER_ATK, FIRST_STRIKE, CHARGE, FORMATION, PURSUIT, SIEGE_ATK, MOVE_UP, REGEN, TERRAIN_MASTER, MATCHUP_NEGATE (조건부 `when` 포함).
- 미지원 패시브(설계만): T_RANGE_UP, T_MORALE_RESIST (+ 오라 계열은 별도 aura 시스템).
- 액티브 지원(Engine::ACTIVE_TEMPLATES): STRIKE, AOE, BUFF, HEAL, SURGE, PIERCE, STANCE (MP 방식 기본 on, active_skills on). 미지원: T_ACTIVE_DECOY(공성계, 송서사 근거 확인 대기).
- 봇 AI: HeuristicBot이 use_skill을 계획함(strike/aoe/surge 등). 아군 NPC(ally_npcs, a측)는 영웅 행으로 만들어져 패시브·액티브 보유/기본 주입을 받아 스킬을 씀.
- **스테이지 적 지휘관/부대는 hero 행이 null로 생성(makeUnit(..., null))이라 패시브도 액티브도 없음**. 적 npc_ref는 이름 표시용. PvP b측 기본 액티브는 enemy_default_skills=false로 꺼짐.
- 아군 NPC 영웅: 스테이지 129개에 distinct 139명 등장, 이 중 126명이 스킬 0(기본 액티브만).

## 3. "전부 만든다" 갭 (범위 가정별)

범위 A: 수집형 202명 마무리(권장 1차)
- 스킬 전무 12명: 신규 설계 12명 x (A 2P+2A, B 2P+1A) = 패시브 24, 액티브 18 정도(A 6명 x 4 + B 6명 x 3 = 42스킬).
- B 43명 액티브 신규 43, C 3명 액티브 신규 3, 기타 규칙 충족 보강. 합계 신규 스킬 약 88~90개.
- redistribution 밖 67명 등급 규칙 맞춤 점검 필요(부족분은 위 숫자에 일부 포함, 감사 확장 필요).
- 주인공 10명 액티브 신규 10(캠페인 서사 스킬).

범위 B: 아군 NPC로 나오는 영웅 139명 중 스킬 0인 126명
- 1인 B/C 기준 약 1P+1A 최소 = 약 250스킬. 템플릿 공유 코드(`sh_*`류) 활용하면 설계량은 병종x등급 조합으로 축소 가능.

범위 C: 적 NPC 영웅(필드에 나오는 적 지휘관/보스)이 스킬을 쓰게 하기
- 현재 불가: 엔진/데이터 구조상 적은 hero 행이 없음. 선택지 (a) 스테이지 적 지휘관에 hero 연결 필드 추가(박백엔), (b) enemy_default_skills 조정(전 스테이지 난이도 재측정 필요). 난이도 계약(승률 40~60%)이 흔들리므로 별도 단계.

범위 D: 캠페인 NPC 410명 전원
- 스킬 0인 390명. 대부분은 지휘관/병사 이름 표시용이므로 1단계 대상에서 제외 권장.

## 4. 영웅 1인 표준 구성안 (이미 확정된 규칙을 그대로 사용 권장)

| 등급 | 패시브 | 액티브 | 쿨다운/횟수 규칙(시작값) |
|---|---|---|---|
| S | 3 | 2 (PIERCE/STANCE 허용) | cd 3~6, uses 1~2 |
| A | 2 | 2 | cd 3~4, uses 1~2 |
| B | 2 | 1 | cd 3~4, uses 1~2 |
| C | 1 | 1 | cd 3, uses 2 (기본 액티브와 동일) |

- 일관성: 전투는 MP 방식이므로 MP 비용(MpRules)이 사실상 규칙이고 cd/uses는 호환 값. 병종 기본 액티브 파라미터(default_active_skills.json)와 같은 범위 안에서 설계.
- 패시브 템플릿은 영웅 내 중복 금지(감사 규칙), 지형 특화·MATCHUP_NEGATE는 S 전용 정책 유지.
- 기본 주입 액티브는 "영웅 고유 스킬이 있다"로 세지 않음. 사용자 "다 만들어"를 충족하려면 B/C의 기본 의존 46명도 고유 액티브로 치환해야 함.

## 5. 단계별 실행안

1. 1차(소규모): 스킬 전무 12명 + C 3명 + 주인공 10명 설계 -> 송서사 이름/설명 -> 시드 -> 감사(`game:audit-skills`) -> 대표 시뮬. 목표 신규 약 50.
2. 2차: B 43명 액티브(병종·등급별 대표 템플릿 풀에서 배정) -> 이펙트 매핑 재생성 -> 계열별 시뮬 보정.
3. 3차: redistribution 밖 67명 감사 확장·규칙 맞춤, 아군 NPC 126명 중 스테이지 비중 큰 순으로 최소 구성(1P+1A) 부여.
4. 4차(결정 필요): 적 지휘관 스킬 사용. 박백엔 엔진 작업 + 전 스테이지 승률 밴드 재측정(40~60%) 필요.
5. 각 단계: 데이터 백업 -> 개발 DB 시드(멱등) -> 감사 -> 시뮬(동일 시드 전후 비교) -> 사람 플레이 확인.

## 6. 사용자 결정 사항

1. "영웅급" 범위: 수집형 202명만(권장) vs 아군 NPC 139명 포함 vs 캠페인 NPC 410명 전원.
2. B/C 등급도 고유 액티브를 전원 부여(기본 주입 대체)할지 현행(기본 주입 허용) 유지할지.
3. 적 NPC 영웅이 스킬을 쓰게 할지(난이도 영향, 박백엔 엔진 작업 포함).
4. 아프리카/아메리카 NPC 스킬은 보류 여부(메모리 지침상 보류 권장).
5. 이펙트: 기존 7계열 재사용으로 충분한지 영웅 전용 연출을 원하는지.
6. DECOY(공성계)/RANGE_UP/MORALE_RESIST 구현 여부와 송서사 근거 확인 선행.

## 7. 사람이 확인할 것 / 한계

- 위 인원수는 DB 쿼리 사실이나, "영웅급" 정의에 따라 범위가 달라 신규 스킬 수는 견적(약 50~250).
- 신규 스킬 수치와 템플릿 배정은 시작값이며 미측정. 시뮬은 이번 단계에서 실행하지 않음.
- 적 스킬 미사용은 코드 읽기 결과이며 실제 전투 로그로 교차 확인하지 않음.
