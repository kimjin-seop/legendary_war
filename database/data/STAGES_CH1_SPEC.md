# 캠페인 ch1 스테이지 데이터 초안 (stages_ch1_proposal.json)

작성: 임밸런. **초안 / 모든 수치는 가정값(시작값)**. 기존 `stages.json`·`maps.json`·`presets.json` 미수정, GameSeed 미연결(이 파일은 아직 시드되지 않음). 밸런스 최종 조정은 슬롯 곡선 개편 이후 마지막 단계에서 재측정한다.

## 1. 팀장 결정 반영
- Q1 병행: 코드 `ch1_s1~s7`, sort_order 101~107, ch1_s1 prerequisite=null, 이후 직전 스테이지 체인. 기존 stage_01~06 해금·퀘스트 불변.
- Q2 목표 객체: `{type:'defeat_commander'}`, `{type:'survive_turns', turns:N}`.
- Q3 파티 2슬롯(Lv1~9) 전제. 플레이어 편성은 실질 4~6유닛(영웅 2 + 부대; max_cost 16~20).
- Q4 적 규모 점증: 지휘관 포함 유닛 수 3 / 4 / 5 / 7 / 6 / 5 / 9 (s6은 의도적 하락). 유닛 상한 clamp 16 이하(최대 9, 기본 max_units 12 이내).

## 3. 설계 의도
- 병종은 상성(칼>창>기>칼, 궁 원거리)을 쓰되 일본군 고유 병종/무기(조총 등)는 시스템에 없으므로 `archer`를 원거리 대용으로만 쓴다(사실 창작 아님). 영웅 데이터가 있는 일본 측 인물(오다 노부나가 등)은 임진왜란 참전자가 아니라서 **쓰지 않았다**. outline의 적 지휘관은 이름만 표기(CSV 미등재, 대사·스탯 서사 없음). 확인 필요(verify) 지휘관은 실명 비표기.
- s1~s3: 3→5유닛으로 소규모 점증, 적 레벨은 권장 이하(실효 1)로 두어 유닛 수 증가가 난이도를 주도.
- s4/s6 방어전: 성문 병목(pk_06, 열 9 벽 + 행 7~8 개구부). s4는 근접 중심 7유닛 정면 압박, s6은 원거리 중심 5유닛·적Lv3로 약화.
- s5 공성: 아군 공격(pk_18, 해자+2성문). 적은 수비 위치, 지휘관은 성 안.
- s7 보스: 지휘관 HP x1.3(가정), 9유닛, 기병·중장갑 포함 최대 규모.

## 4. s6 난이도 하락 사유
1. 같은 맵(pk_06) 재사용이라 적 규모·레벨을 낮춰 반복감을 줄이고 s5(공성)->s7(보스) 사이에 숨 돌릴 구간을 두는 페이싱.
2. s6은 권율 합류(게스트) 스테이지로 성취감(승리 경험) 비중을 둠. 방어 성(성 +30 방어)에서 원거리 유닛이 성문 앞에 몰리는 구도라 s4보다 대응이 쉬움.
3. 단 이는 설계 의도이며 실제 하락폭은 **미측정**(survive_turns 엔진 미구현). 사람 플레이 후 판단.

## 5. 보상 곡선 / 반복 횟수 가정
- 입력(사실): `user_level_costs.json` exp_to_next Lv1~6 = 60,158,279,417,571,737 -> Lv7 누적 2,222. 기존 stage_01~06 user_exp = 30/45/65/90/125/175(합 530), 영웅 exp:user_exp = 2:1, gold ≈ user_exp x 2.9~3.3. 현재 설정 `retry_mult`=1.0(재도전 감소 없음, config/game.php), star_mult 1.0.
- 가정: 스테이지 k 진입 전 Lv >= 권장Lv가 되도록 직전 스테이지를 반복(재도전 배율 1.0), 첫 클리어 보상 = 반복 보상(동일). 기존 stage_01~06 파밍은 제외.
- 산술 결과: ch1 첫 클리어 user_exp 합계 565. 반복 횟수 s2 2, s3 4, s4 4, s5 4, s6 5, s7 6회(합 25회 반복, 총 약 32판)에 Lv7 도달(경험치 2,445, 가정 하). `retry_mult`=0.5로 바꾸면 반복이 48회(총 약 55판)로 늘어 노동 과다 위험 -> retry_mult 도입 시 보상 재조정 필요. 기존 stage_01~06 병행 파밍을 허용하면 필요 횟수 감소(스테이지 간 중복).
- 영웅 exp(2배)·gold는 비례 가정. 영웅 레벨 곡선(hero_levels) 대비 검증은 **미측정**.

## 6. 시뮬레이션 (읽기 전용: `game:simulate --sections=level --by-stage --stage-set=...`)
방법: DB는 개발 SQLite, 쓰기 없음. `stage_01`을 메모리 패치(--stage-set)해 맵/적Lv/extra만 교체, 도커 순차 실행(동시 1).
한계(중요): (a) 적 지휘관을 영웅 프리셋으로만 지정 가능 -> 프록시로 stage_01의 p_hildegard 사용(일반 지휘관 아님). (b) 플레이어 = 101영웅 순환(평균 영웅)·지휘관1+부대3 고정 4유닛, 양측 교대, 이순신 전용이 아님. (c) 목표/별 조건/성 방어 비대칭 시뮬 불가, 적 유닛은 프리셋 부대3(+extra), 3유닛 적 불가. (d) `-2/0/+2`는 플레이어 Lv-권장Lv. 판수 100~300 -> 95% CI는 최대 약 ±8%p.

관찰(시뮬 한정): 적 유닛 +1은 4v4 평균영웅 기준 승률을 크게 떨어뜨리고(+0에서 약 -15~30%p), 적Lv +1은 약 -15~20%p. 따라서 수 점증 + 적Lv 하향 조합을 채택. **프록시 승률은 평균 영웅 기준이라 목표 대역(예: s1 80%+, s3 50~60%)과 직접 비교 불가** -> 이순신 고정/실제 편성 시뮬은 별도 필요. 현 수치로 s3(5유닛)은 과하게 어려울 가능성(가설, 약한 근거) -> 사람 플레이 후 4유닛 또는 적Lv 유지 대안 검토. s4~s7은 **미측정**.
평균 턴·턴 제한률·선공/후공 편향·치유 사용·첫 턴 킬은 이번 섹션 출력에 없어 **미측정**(turn_within 별 조건 값 8~12는 근거 없는 가정).

1. 적 레벨 offset(0,-1,-2,-1,-1,-3,-2), 적 유닛 수/병종, 지휘관 hp_mult s7=1.3(그 외 1.0).
2. 보상 user_exp 25/35/55/80/110/100/160, exp=x2, gold 표 값.
3. 반복 횟수 가정(retry_mult=1.0, 첫 클리어=반복 보상).
4. 별 조건 turn_within 값은 outline 그대로(검증 안 됨), 생존 스테이지 대체 조건 `commander_hp_pct_min 50`은 임밸런 제안(문기획 승인 필요).
5. 게스트 영웅은 파티 슬롯·코스트 상한과 무관하게 추가 출전한다고 가정(Q3 2슬롯과 충돌 가능 -> 확정 필요).
6. s5 맵 pk_18(28x20)의 성능/렌더는 미검증 가정.

## 8. 박백엔에게 넘길 스키마 요구사항 (엔진/시드 변경, 임밸런은 코드 불가)
1. `stages`: `objective` JSON(`defeat_commander` | `survive_turns{turns}`), 승리=N턴 종료 시 플레이어 지휘관 생존(타 조건 없음), 패배=지휘관 사망. 턴 제한 규칙(alive_then_ratio)과의 상호작용 명시, max_turns 30 > 9 확인.
2. 적 편성: 영웅 없는 일반 지휘관. `enemy_presets[]` {code,name,commander{display_name_ko,unit_type,hp_mult,atk_mult,def_mult,aura,skills}, units[](길이 가변 0~15)}. 현재 프리셋은 영웅 필수·부대 3개 고정이라 s1(2부대)·s7(8부대) 표현 불가. 임시 호환으로 JSON에 `enemy_extra_troops`(units[3:])도 병기했으나 s1은 2부대라 호환 불가. 총 유닛 clamp 16.
3. `star_conditions`(JSON 배열): clear / all_alive / turn_within(value) / commander_hp_pct_min(value). 현재 별 계산은 BattleService 하드코딩(HP>=50%, 15턴 이하)이라 스테이지별 조건 필요. 각 조건 판정은 `result.stars` 산출과 연결.
4. `guest_heroes`(스테이지 출전 강제/게스트): 파티 슬롯 규칙과의 관계, 코스트 계산, 미보유 영웅 처리 필요. `join_hero`(first_clear)는 별도 보상 처리(최초 클리어 시 영웅 지급).
5. 시드: 신규 파일 병합 시 idempotent(code 기준), `maps`는 이미 pk_* 로드됨(DB 확인: pk_01=151, pk_02=152, pk_19=163, pk_06=169, pk_10=164, pk_18=170, pk_12=165, pk_20=168). `map`은 code로 매핑.
6. 시뮬: `game:simulate` 레벨 섹션이 `enemy_preset_id`→영웅 가정이라 일반 지휘관/목표 survive를 지원하도록 확장 요청(승률, 평균 턴, 턴 제한률, 선후공 편향 출력). 구현 후 s4~s7 측정.
7. survive_turns UI/로그: 남은 턴 표시(FE는 윤프론).

## 9. 사람이 확인할 항목
- s1~s3 첫 플레이 체감(이순신+곽재우 편성), s3 난이도(5유닛 적)가 과한지.
- s4/s6 성 방어 체감 차이와 s6 하락폭, 8·10턴이 적절한지.
- 반복 횟수 25회 전후가 지루하지 않은지(기존 stage_01~06 파밍 허용 여부 포함).
- 보스 s7 HP x1.3과 9유닛의 대규모 느낌, 맵(pk_10)에서 병목 양상.
- 일본 측 지휘관 이름 표기(accepted/verify 구분)와 문기획 근거 수준 일치.

재측정: **미측정**. `game:simulate` 스테이지 섹션은 적 부대를 영웅 프리셋 3부대(+extra)로만 구성하고 병종 단일 일반 지휘관을 만들 수 없으며, formation 섹션은 맵 지정이 불가능해 s1~s3 맵 조건 재현이 안 된다. v1 프록시 수치는 6절 그대로이며 v2와 직접 비교 불가. 일반 지휘관 지원 시뮬 확장(8절 6번) 후 측정.

박백엔 스키마 요구사항(추가):
1. `enemy_presets[].commander.troop_type`(sword|spear|cavalry|archer, 생략 시 commander.unit_type) 추가, 검증: 허용 병종 외(heavy 등) 값은 시드 단계에서 거부.
2. `addGenericSide`에서 정규화: units[]의 각 항목을 commander.troop_type 1종으로 통일(길이는 유지). 파일은 이미 단일 병종으로 작성되어 있으나 서버가 방어적으로 강제(혼합 입력 시 경고 로그).
3. 지휘관 자신의 병종은 commander.troop_type과 동일. 지휘관 hp_mult/atk_mult/def_mult는 지휘관 유닛에만 적용.
4. enemy_extra_troops 호환 필드(units[3:])도 단일 병종으로 갱신해 둠.
5. 시뮬(`game:simulate`)이 일반 지휘관+단일 병종 편성을 지원하도록 확장(가변 길이, 맵 지정, 선후공·평균 턴 출력).
