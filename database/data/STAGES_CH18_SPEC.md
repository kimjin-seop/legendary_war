## 1. 사실 / 가정 구분
- 사실(코드·데이터 확인): `game:simulate` 스테이지 섹션은 아군 영웅 1명이라 권장 편성을 못 만든다 -> 기존 `bal.php` 방식(양측 HeuristicBot, 아군 다영웅, 플레이어 선공, 적은 `EnemyV3Adapter` 변환)을 ch18용으로 복제해 측정. `user_level_costs.json` party_slots Lv10~19=3, Lv20~=4. `troop_slots` hero Lv10~19 = 영웅당 부대 3. 개발 DB heroes에 `genghis_khan`(S, cavalry, 비-campaign_only)과 `npc_jebe/npc_subutai/npc_muqali/npc_boorchu`(campaign_only, id 1555~1558)가 이미 있다. 맵 지형 타일은 기존 것만 쓴다(신규 타일 없음).
- 가정: 권장 레벨 10~17, 아군 3영웅(이야기 영웅 1~2 + 플레이어 영웅 평균 1~2)=12유닛, 보상 비율, 별 조건 턴 수, 승률 밴드 전부.
- 한계(중요): 측정의 "플레이어"는 봇이 조종하는 임의 영웅(풀 평균 + 이야기 영웅)이다. 사람 플레이 승률과 다르다. 시드 간 편차 약 ±4~8%p.

## 3. 스테이지별 설계 의도
- 공통: 아군 12유닛(3영웅 x (1+부대3)) 가정, 적 부대는 지휘관 1 + 단일 병종 병사(v2 규칙). 지휘관은 실명이 불확실하면 일반 지휘관(실명 비표기). `ai`는 데이터 보존만(엔진 미지원 시 advance 폴백).
- s1: 입문. 나이만 계열 잔당 습격은 **각색**(역사 전투 아님). 3부대 8유닛.
- s2: 서하 변경 수비선. 처음 pk_11(산악 통로)을 썼으나 봇끼리 대치해 턴 제한 종료가 약 20%라 pk_13_crossroads로 교체(턴 제한 0%).
- s3(선택): 금 야전군. 레벨 offset이 거의 효과가 없어 지휘관 HP로 난이도를 맞춤(x3.0은 보스급, 사람이 체감 확인).
- s4: 제베 주도. 칭기즈 칸 불참. 쿠출루크의 최후는 서술하지 않는다.
- s5: 도하 후 점령형. 처음 15유닛은 93~98%로 너무 쉬워 21유닛(heavy 호위 추가)+offset +1+점령 3턴으로 상향. 적 대 아군 비율이 1.75라 높다(사람 확인).
- s6(선택): 잘랄 앗딘 추격. 사망 단정 금지, 연출은 패주/도하 탈출.
- s7: 칭기즈 칸 **출전 제외**(excluded_heroes). 루스-킵차크 연합의 도착 시차를 3턴 증원으로 표현. 최초안의 5턴 킵차크 증원은 난이도 초과로 제거.
- s8: 보스 스테이지. 사망 연출 없음. 목표 하한 55~65%.

## 8. 박백엔·다른 팀원 요청
1. 박백엔: ch18용 시드(`game:seed-imjin10 --enemy=` 형식이 v3 문서만 읽으므로 ch18 stages 행 신규 insert 지원 또는 `game:seed-ch18` 필요). 필요 필드: 본 JSON items[] 전부, `excluded_heroes`(s7 칭기즈 칸 출전 제외), `objective.points` 직접 지정 점령.
2. 박백엔: 영웅 승격 코드 규칙(npc_ 유지 여부)과 초상화 키 철자 불일치(mukhali/borchu) 연결.
3. 엔진 요청: 지휘관 HP 외 약한 노브가 많다. 레벨 offset 효과 불규칙(0~15%p/단계)이라 적 병사 레벨 가산(`level_delta`) 노브가 있으면 미세조정이 쉽다. 검증은 bal18 하네스 동일 시드.
4. 재현: scratchpad의 defs.py/gen18.py/tune.json/bal18.php(컨테이너 /tmp에 복사 후 `php /tmp/bal18.php '{"stages":["ch18_s1"],"n":150,"seed":31}'`). 동시 8프로세스 이상은 CPU 경합으로 매우 느리다(순차/4개 이하 권장).
