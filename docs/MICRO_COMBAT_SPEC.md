# 병사 미시 교전 규칙 (1단계, 서버 전용)

구현: `app/Game/Micro/MicroCombat.php`, 연동: `Engine::doAttack` / `Engine::microEngage`. 테스트: `tests/Unit/MicroCombatTest.php`.
**모든 수치는 임시 시작값**이다. 임밸런이 그림자 모드로 튜닝하며 최종 값이 아니다. FE 컷신 재생기(윤프론)는 이 문서의 "이벤트 필드"를 기준으로 만든다.

## 1. 범위
- 맵 유닛 1기 대 1기 교전(`doAttack`의 일반 공격) 안에서 병사 군집(병력 1~10)이 개체별로 싸운다. 여러 유닛 합류 교전은 범위 밖.
- 제외(기존 공식 유지): 액티브 스킬 교전(`via_skill`), AOE, 지휘 범위.
- 영웅/지휘관(`kind != troop`)은 단일 개체 1. 영웅이 쓰러지면 부대 붕괴는 기존 `resolveDeath` 그대로.

## 2. 스위치 `micro_mode` = off | shadow | on
- `config('game.rules.micro_mode')` (기본 `off`, 환경변수 `GAME_MICRO_MODE=off|shadow|on`, 잘못된 값은 off). 전투 생성 시 `ArmyBuilder::initialState(..., $microMode)`가 `state['micro_mode']`에 고정한다. **off면 키를 기록하지 않는다**(구 전투도 off 취급, 기존 state·이벤트와 바이트 동일).
- shadow: 기존 공식으로 확정한다. HP·kill·counter 이벤트와 기존 `attack` 필드는 off와 동일하고, `attack` 이벤트에 `micro` 필드만 추가된다. 미시가 `state['rng']`와 `event_seq`를 건드리지 않는다.
- on: 미시 결과로 확정한다. 방어측 HP = `micro.hp_after[1]`, 공격측 HP = `micro.hp_after[0]`, `attack.dmg` = 방어측 손실. 공격측 손실이 있으면 `counter` 이벤트 1회(`dmg` = 공격측 손실, 기존 FE 호환). **사용자 승인 전 켜지 않는다.**
- `micro_no_snowball`(기본 true): shadow/on의 개체 타격 산출에서만 스노볼 가산을 뺀다(병사 수 우위와의 이중 가산 방지). off 경로 불변.
- 튜닝값 덮어쓰기: `config('game.rules.micro')` 배열(키는 `MicroCombat::DEFAULTS`).

## 3. 개체당 기본 타격 피해
교전 시작 시 기존 `damageInfo`를 1회씩 호출해 재사용한다(상성·지형·오라·패시브·버프·수상·방향 배율 중복 구현 없음).
- 공격측 D_att = `damageInfo(공격자 -> 방어자)['dmg']`(방향 배율 포함). 방어측 D_def = `damageInfo(방어자 -> 공격자, counter=true)['dmg']`(정면 취급).
- 병사 1타 = `max(1, round(D x dmg_pct / 1000))` (D/10 x dmg_pct%). 영웅 단일 개체 1타 = `max(1, round(D x dmg_pct/100 x hero_dmg_mult))`.
- 병사 HP: 병력 n = `ceil(hp x 10 / max_hp)`(1~10), HP를 n명에 정수 분배(앞 개체부터 +1). 병사 한 명은 평균 3~4타에 쓰러진다(기본값 기준).
- 화력은 생존 병사 수에 비례하므로 수가 많은 쪽이 자동으로 유리하다.

## 4. 영웅 개체 노브 (영웅 1 대 병사 N)
| 키 | 기본(임시) | 의미 |
|---|---|---|
| `hero_hp_mult` | 0.7 | 영웅 개체 HP 배율. 교전 후 `ceil(생존HP / 배율)`로 환산해 실제 hp_after에 반영(원래 HP 초과 불가) |
| `hero_dmg_mult` | 1.0 | 영웅 1타 배율 |
| `hero_attacker_cap` | 6 | 영웅 1체를 동시에 때릴 수 있는 근접 적 수(포위 한도) |
| `hero_incoming_pct` | 100 | 영웅 피격 1회당 피해 %(포위 감쇠. 100=감쇠 없음) |
- 영웅 노브는 영웅 개체에만 적용되므로 영웅 대 영웅, 부대 대 부대의 상대 균형은 노브와 무관하다(영웅 대 영웅은 양쪽에 같은 배율이 걸림).
- 기본값 측정(동일 HP 100, 기본 타격 D=30, 반복 교전으로 결판): 영웅 1체가 같은 병종 병사 9명까지 이기고 10명(전 병력)에게 진다. 임밸런 튜닝 대상이며 영웅 크기는 컷신에서 병사와 같은 표시 높이를 유지한다(FE).

## 5. 틱과 결정성
- 1틱 = `tick_ms`(10ms), 교전 = `ticks`(109) 틱 = 1090ms(컷신 타격 교환 10박x105+40). 한쪽이 먼저 전멸해도 `ticks`/`tick_ms`는 고정(재생 길이 불변).
- 동시 전멸 방지: 한 틱에 양측 생존 개체가 모두 0이 되면 교전 개시측(역할 0)의 그 틱 사망 개체 중 번호가 가장 낮은 1기를 HP 1로 생존시킨다(동점 상황에서만 작동, 결정적).
- 정수 연산만, 난수 없음, `state['rng']` 미사용. 같은 입력이면 같은 출력. 동점 규칙은 전부 결정적(아래 6).
- 같은 틱의 피해는 동시 적용 후 사망 판정(처리 순서 편향 없음). 이미 쓰러진 적은 새로 때리지 않는다(같은 틱 동시 타격에 의한 과잉 피해는 허용).

## 6. 타깃·이동 규칙 (상수는 DEFAULTS)
- 좌표: 1칸=100 서브유닛 정수 격자. 슬롯 좌표 테이블 `MicroCombat::LAYOUTS`(진형 이름 => 개체 순서별 [열,행], 열0=전열/행2=중앙 레인). 기본 `grid2x5`(2열x5행, 중앙 행부터 채움)도 표의 한 항목이며 입력 `layout` 키로 선택(진형 5종은 이 표에 항목 추가). 실제 좌표 = 열 x `spacing_x`(150), 행 x `spacing_y`(150): 현행 100보다 넓혀 10기가 겹치지 않고 모양이 읽히게 함(조정 가능). 공격측 전열 x=300, 방어측 전열 x=300+`gap`(300). 영웅 단일 개체는 [0,2]. 개체 번호 = 공격측 0..n-1, 방어측 이어서.
- 거리 = 맨해튼. 사거리 = 병종 `range_max` x 100(근접 100).
- 대상 선정: 살아있는 적 중 (1) 거리 최소(= 같은 레인 우선) (2) 부착한 근접 공격자가 적은 적 (3) 낮은 HP (4) 개체 번호. 대상이 쓰러지면 **같은 틱** 말에 같은 규칙으로 재선정(이동·타격은 다음 틱부터).
- 동시 근접 공격자 상한 `attacker_cap`(3, 영웅은 `hero_attacker_cap`). 상한 때문에 대상이 없는 근접 개체는 가장 가까운 적으로 접근만 하고 대기. 원거리는 상한 없음.
- 이동: 사거리 밖이면 대상 쪽으로 틱당 `speed`(foot 10, mounted 15, flying 12, naval 10 서브유닛) 이동. **대각 이동 없음**: 거리 큰 축 먼저(동률이면 x), 남는 이동량은 다른 축. 병사끼리 충돌·밀침 없음(겹칠 수 있음). 원거리는 사거리 안이면 제자리 사격, 밖이면 접근.
- 타격: 사거리 안 + 대기 완료 시 타격 후 `attack_period`(30틱) 대기. 첫 타격 대기는 개체 번호 %5 -> [0,6,12,18,24]틱(사거리 진입 후부터 흐름).
- 비행 "장벽 무시": 아레나에 장애물이 없어 현재는 속도 차이로만 반영(확인 필요: 지형 반영 시 재정의).
- 방어측도 사거리 안이면 반격한다(기존 공식의 "원거리 간 무반격"과 다름. 확인 필요).

## 7. 이벤트 필드 (`attack` 이벤트의 `micro`, shadow/on)
```
micro: {
  mode: 'shadow'|'on', v: 1, tick_ms: 10, ticks: 109,
  hp_after: [공격측, 방어측],   // 미시 결과(실제 HP 단위). shadow에서는 기존 공식 hp_after와 다를 수 있음
  alive: [공격측 생존 수, 방어측 생존 수],
  s: [[side(0=공격,1=방어), x, y, hp], ...],   // 개체 초기 상태. 배열 인덱스 = 개체 번호
  k: [[개체, tick, x, y], ...],     // 이동 키프레임: 해당 틱 경계의 위치. 다음 키프레임까지 선형 보간(속도가 바뀔 때만 기록). 없으면 정지
  h: [[tick, 공격개체, 대상개체, 피해, 대상 hp_after], ...],   // 타격
  d: [[tick, 개체], ...],           // 사망(그 틱 타격으로 쓰러짐)
  r: [[tick, 개체, 새 대상|-1], ...] // 대상 선정/재선정(-1=대상 없음). 연쇄 이동 연출용
}
```
- 시간(ms) = tick x tick_ms. 사망 개체의 이동 키프레임은 사망 틱+1에서 멈춘다.
- 크기: 10 대 10 기본값에서 약 2.0KB(JSON). `redactEvents`는 `mp_change`/`skill_use`만 가리므로 `micro`는 그대로 통과하고, `RoomService::poll`은 저장된 이벤트를 그대로 읽는다. shadow/on 전투만 이벤트가 커진다(off는 불변).

## 8. 가정·확인 필요
- 액티브 스킬 교전 미시 제외, 영웅 단일 개체, 방향 배율은 교전 전체 배율(D에 포함), 지휘 범위 제외, 컷신 길이 ±0.2초, 서버 시간은 현행 교전 처리의 2배 이내(측정만).
- 대각선 접근 미허용(최소 규칙). 원거리 상호 사격 허용. 비행 장벽 무시 미구현(장애물 없음). 수치 전부 임시.

## 9. 진형 (2단계)
기본 `micro_mode=off`와 기존 `grid2x5` 경로는 바뀌지 않는다. 진형은 입력 `formation` 키(영문 코드) 추가 방식이며, 없으면 `grid2x5`다. 피해·HP 수치 가산은 없고 배치·타깃·접촉 구조만 다르다. **영웅 개체는 진형에서 제외**(항상 grid2x5, 슬롯 [0,0]).

| 코드 | 이름 | 형태(슬롯 `MicroCombat::FORMATIONS`) | 이동 속도 % | 접촉 상한 cap | 타깃 |
|---|---|---|---|---|---|
| `crane` | 학익진(포위형) | V자 날개가 적 쪽으로 굽음 | 100 | 3 | spread(덜 공격받는 적 우선 = 분산·측면 접근) |
| `fish` | 어린진(돌파형) | 쐐기(꼭짓점이 적 쪽) | 115 | 3 | nearest |
| `phalanx` | 방진(방어형) | 3x3 조밀 사각 + 후미 1 | 85 | 2 | nearest |
| `line` | 횡대(확장형) | 가로 한 줄(10칸 폭) | 100 | 4 | nearest |
| `circle` | 원진(방어형) | 원형, 마지막 2슬롯이 중심 약병 | 90 | 3 | nearest |
| `grid2x5` | 기본 | 2열x5행(기존) | 100 | 3(전역) | nearest |

- `cap` = 그 진형의 개체 1기를 동시에 때릴 수 있는 근접 적 수(접촉 상한). `speed_pct` = 틱당 이동량 %. `target=spread`는 키 순서를 [부착 공격자 수, 거리, HP, 번호]로 바꾼다. 값은 `MicroCombat::FORMATION_RULES`(임시값)이며 `config('game.rules.micro.formation_rules')`로 진형별 덮어쓴다.
- 좌표: 진형 슬롯 `[열,행]`, 행 0=중앙 레인, y = 300 + 행 x `spacing_y`(간격 상수 `spacing_x/y` 그대로). 병력이 10 미만이면 앞쪽 슬롯부터 채운다.
- 3군 순환(돌파>확장>방어>돌파)은 규칙이 아니라 구조에서 나와야 한다. 현재 기본 노브(dmg_pct 60·attack_period 60)에서 10 대 10 양방향 평균 HP 차는 +-4 이내로 작고(방진>어린 +2, 횡대>방진 +1, 어린>횡대는 -2로 순환이 한 고리 어긋남), 임밸런이 `formation_rules`(speed_pct/cap/target)를 후속 측정·튜닝한다.
- 진형 결정: 병사 유닛의 `formation`(적 부대: 스테이지 데이터 `enemy_squad.formation` 또는 `squads[].formation`에 한글 이름/영문 코드; 없으면 키 없음) > 소속 영웅(`leader_id`)의 `database/data/hero_formations.json`(`{hero_id:{formation,alt,reason}}`, formation은 한글/코드) > 기본 `grid2x5`. 파일이 없거나 키가 없거나 알 수 없는 진형이면 폴백. 로더: `App\Game\Micro\FormationBook`. `docs/data/hero_formations.draft.json`은 초안이며 로더가 읽지 않는다(`database/data/`로 복사하는 것은 별도 결정).
- 이벤트: `micro.formation`(`[공격측, 방어측]` 코드, 기본 `grid2x5`)과 `micro.formation_ko`(`학익진` 등, 기본 `기본`).

## 10. 고정소수·이벤트 보강 (2단계 후속)
- **고정소수**: 내부 HP·피해를 `hp_scale`(기본 100)배 정수로 계산한다(영웅 배율은 천분율 정수). 지형 +20%/+30%, 상성 1.25배, `dmg_pct`/`hero_dmg_mult`가 정수 양자화로 사라지거나 계단형이 되던 문제를 없앤다. `hp_after`만 원래 HP 단위로 환산(올림, 생존 시 최소 1).
  - 확인(임밸런 `mp4.php` K=1, 1개체 25% 기준): 평지 25 -> 숲 방어 -10% 22 / 산 -20% 20 / 상성 1.25배 31. 이는 소수 개체 타격 횟수 이산화 때문에 22.5/20/31.25가 22/20/31로 나온 값이다.
  - 이벤트 `s`/`h`/`e`/`m`의 HP·피해는 **스케일 단위**(실제 HP x `hp_scale`)다. 표시용 HP는 `/hp_scale`.
- **기본 노브(임시, 임밸런 H1 후보)**: `dmg_pct` 60, `attack_period` 60, `hero_attacker_cap` 10, `hero_dmg_mult` 0.5, `hero_hp_mult` 0.9(영웅 9승·10패에 맞춰 0.7에서 조정). 측정(mp2.php): 영웅 대 병사 9명 승(잔여 12%), 10명 패, 10 대 7 잔여 57%, 10 대 10 1교전 손실 26%(legacy 21%, 편차 있음 -> 임밸런 후속).
- **컷신 정합(사망 0인데 HP만 줄어드는 문제)**: 사망 규칙은 바꾸지 않고, 이벤트가 개체별 HP 비율을 FE에 준다. `m`=개체 최대 HP(스케일), `s`=시작 HP, `h`=타격마다 대상의 남은 HP, `e`=종료 시 생존 개체의 [개체, 남은 HP]. FE는 막대 = HP/`m`으로 그린다. `hp_before`=[공격측, 방어측] 교전 시작 유닛 HP. 병사 수(생존 `alive`)와 `hp_after` 불일치는 막대로 설명된다(병사 수 표시는 기존 `ceil(hp/max_hp x 10)` 유지).
- **`end_tick`**: 마지막 이벤트(타격·사망·이동) 틱 + 1(없으면 0, 최대 `ticks`). 한쪽 전멸로 일찍 끝나면 109보다 작다. `ticks`/`tick_ms`는 계속 고정(재생 길이 불변), FE가 길이를 줄일지 판단하는 용도.
- **사용자 결정 대기 옵션(기본 현행 유지)**: `legacy_counter`(false=현행, 방어측이 사거리 안이면 항상 반격 / true=기존 공식 규칙, 근접끼리만 반격하고 원거리가 낀 교전은 방어측 무반격), `first_strike_phase`(0=off, N틱만큼 방어측 첫 타격을 늦춰 선공측에 위상 이점. 20이면 10 대 10 손실이 공격측 27% 대 방어측 36%).
- **on 모드 지휘관 처치**: 방어측 지휘관(영웅 개체) `hp_after`가 0이면 기존 `resolveDeath`가 그대로 승패를 낸다(테스트: off와 동일하게 `finished`, 승자 a, 종료 이벤트 발생).

## 11. 적용 준비 (서버)
- **환경변수·화이트리스트**: `GAME_MICRO_MODE`(기본 off), `GAME_MICRO_STAGES`(쉼표 구분 스테이지 code 또는 id), `GAME_MICRO_ROOMS`(방 code). 둘 중 하나라도 비어 있지 않으면 **목록의 스테이지·방만** 모드가 적용되고 나머지(다른 스테이지·방·시즌 전쟁)는 off. 둘 다 비면 전체 적용. 판정은 `Engine::microModeFor(scope, keys)`이며 `BattleService`(스테이지)·`RoomService`(방)·`WarService`(항상 `other`)가 전투 생성 시 한 번 호출해 `state['micro_mode']`에 고정한다. 진행 중 전투(save/resume)는 state에 고정된 값을 쓰므로 설정을 바꿔도 영향이 없다(구 전투는 키 없음 = off).
- **shadow 점검**: shadow는 legacy 결과로 확정한다(HP·kill·counter·`rng`·`event_seq` 불변, `attack.micro` 필드만 추가: 테스트 `test_shadow는_기존_결과와_이벤트를_유지...`). 같은 시드에서 off와 shadow의 승자·턴이 같음을 `game:micro-shadow-report`가 매 판 확인한다.
- **`game:micro-shadow-report`**: `--stages=5 --games=4 --seed=1 --delta=0 --log=<경로> --no-verify`. 스테이지(권장 레벨 오름차순 앞 N개)를 봇 vs 봇으로 자동 진행(DB 읽기 전용, 아군 NPC·동반병 제외)하며 attack 이벤트마다 legacy와 micro를 비교해 스테이지별·합계로 집계한다: 교전 수, 승자 일치율(남은 HP 비율이 큰 쪽), 방어측 처치 일치율, hp_after 차(micro-legacy) 공격측/방어측 평균·절대평균, HP 1 생존 교전 수. 집계는 `--log` 파일(기본 시스템 임시 폴더 `micro_shadow_report_<일시>.log`, storage 로그·테이블 미사용)과 콘솔에 남는다. 컨테이너 one-off로 돌리면 임시 폴더가 휘발하므로 `--log`를 마운트 경로(예: `/var/www/html/scratchpad/...`)로 지정한다. 측정 훅은 `Duel`/`Simulator`의 선택 인자 `eventSink`(기본 null, 기존 동작 불변). 참고 측정(3스테이지x2판, 임시 노브): 승자 일치 65%, 처치 일치 83%, 방어측 hp_after가 micro에서 평균 +13.5(손실이 더 적음) - 튜닝은 임밸런.
- **컷신 정합 `survivors`**: 상호 전멸 방지로 HP 1 생존한 개체는 사망 이벤트(`d`) 없이 끝난다. 이벤트 `micro.survivors` = `[[tick, 개체, hp(스케일 단위, 항상 1)], ...]`(없으면 빈 배열). 해당 개체는 `e`(종료 생존 목록)에도 hp 1로 포함되고, 그 틱 타격 기록 `h`의 잔여 HP는 1로 정정돼 있다. FE는 `d`에 없는 `survivors` 개체를 쓰러뜨리지 않고 HP 1 생존으로 연출한다.
- **진형 속도 이동 유형 오버라이드**: `FORMATION_RULES[진형]['speed_pct_by_move']` = `{foot|mounted|flying|naval: %}`(기본 `[]` = 전 유형 `speed_pct`, 현재 값과 동일). 있으면 그 이동 유형 개체는 `speed_pct` 대신 이 값을 쓴다. `config('game.rules.micro.formation_rules.<진형>.speed_pct_by_move')`로 덮어쓰며 값 조정은 임밸런이다(기마·원거리 순환 어긋남 보정용).

## 11. FE 컷신 재생 (`resources/js/game/fx/MicroCutscene.js`, 2026-11-06)
- 경로: `battleStore`가 `attack.micro`를 연출 이벤트로 넘기고 -> `FxManager.attack` -> `BattleCutscene`(옵션 `micro`). `micro`가 없거나 형식이 다르면(`microPlayable`: v 1, `s`/`m` 길이 일치, 양측 개체, `tick_ms`>0) 기존 연출 그대로다. 액티브 스킬 교전·배 탑승 교전은 기존 연출(배 개체 연출 미구현).
- 재생: 패널·컷인 초상·배경은 기존 그대로, 무대 병사 군집만 개체 스프라이트로 바꾼다. 위치 = `s` + `k` 선형 보간(서브유닛 -> 화면 선형 변환, 가로 최소 1350·세로 최소 600 서브유닛 범위), 타격 = `h`(근접 130 서브유닛 이하 찌르기·불꽃, 초과 투사체 90ms), 사망 = `d`(320ms 쓰러짐), 개체 HP 막대 = HP/`m`(살아 있으면 최소 1px). 길이 = `end_tick` x `tick_ms`(최소 240ms, 사망이 있으면 +190ms) 후 결과 유지 -> 종료.
- 정합: 재생 끝·탭 스킵 모두 `e`로 최종 상태를 맞춘다(`e`에 없으면 쓰러짐, 있으면 그 HP). 동시 전멸 방지 HP 1 생존 개체는 `d`가 없고 `e`에 HP 1로 있어 그대로 서 있다. 패널 병력 숫자·바는 서버 `attack`/`counter`의 `hp_after`(shadow면 기존 공식 결과) 기준이다.
- 진형 이름: `formation_ko`가 `기본`이 아니면 각 진영 군집 위에 약 1.2초 표시. 2026-11-07 진형 제거 결정으로 `MicroCutscene.js` `SHOW_FORMATION=false`(표시 안 함).
- **재생 모드 게이트(2026-11-06)**: `attack.micro.mode === 'on'`(확정값)일 때만 `battleStore`가 `micro`를 넘긴다. shadow(참고용, 맵 HP는 기존 공식)·`mode` 없음은 기존 연출. 서버 필드 추가 없음(`microEngage`가 이미 `micro.mode`를 기록).
- **반격 없음(`legacy_counter=true`)**: 방어측 개체 타격이 0이고 방어측이 살아 있으면 방어측 군집 위에 `반격 없음`을 첫 타격부터 끝까지 표시. 공격측이 원거리(사거리 130 서브유닛 초과 타격 있음)면 방어측 개체 이동 `k`를 무시해 제자리에 둔다(무반격 병사가 다가와 서 있기만 하는 장면 방지). 공격측 근접이면 이동은 서버 그대로.

## 12. 원거리·기병 보정과 on 전환 절차 (2026-11-06)
### 12.1 원거리·기병 진형 규칙
- 문제: 진형 규칙(`cap`=근접 접촉 상한, `speed_pct`)이 원거리 사격에 적용되지 않아 원거리 교전에서 방어측 진형이 결과에 거의 영향을 주지 못했고(사거리 안이면 접촉 상한 없이 전원 사격), 기병은 진형 속도 감속이 보병과 같아 돌격 이점이 사라졌다.
- 신규 노브 `formation_rules.<진형>.ranged_cap`: 그 진형 개체 1기에 동시 사격 가능한 원거리 적 수(밀집·엄폐). `null`(기본)=무제한=기존 동작. 근접 공격자·영웅 개체에는 무관. 사격 슬롯은 표적 선정 시점에 살아서 그 표적을 조준 중인 원거리 수를 매번 계산하므로 사격자가 죽거나 표적이 쓰러지면 자동 반환된다(근접 접촉 cap 도 같은 방식). 한도가 찬 표적은 건너뛰고 빈 표적이 없으면 그 틱은 사격 대기이며 매 틱 재선정하므로 슬롯이 비면 즉시 사격한다(영구 교착 없음). 현재 값: 학익 6, 어린 5, 방진 3, 원진 4, 횡대 null.
- 기병 돌격: 기존 `speed_pct_by_move.mounted`를 config에 설정(학익 90, 어린 100, 방진 80, 횡대 125, 원진 90). 보병 값은 그대로.
- 보병·창·검(근접) 교전 결과는 변하지 않는다(10 대 10 진형 표 전 칸 동일 확인, 테스트 `test_원거리_진형_ranged_cap...`). 롤백: config의 `ranged_cap`·`speed_pct_by_move` 키 삭제.
- 한계: `legacy_counter=true`에서 원거리 공격 시 방어측은 무반격이라 원거리 교전은 공격측 우세가 구조적(기존 공식과 동일 의도). 진형 순환은 원거리끼리 +-10 내외로 약하게만 나타난다. 값은 임밸런 후속 튜닝 대상.

### 12.2 dev에서 특정 스테이지·방만 on 으로 켜기 / 롤백
1. dev `.env`(또는 compose environment)에 설정. 예: `GAME_MICRO_MODE=on`, `GAME_MICRO_STAGES=ch101_s1`(code 또는 id, 쉼표 구분), `GAME_MICRO_ROOMS=<방 code>`. STAGES/ROOMS 중 하나라도 있으면 목록의 스테이지·방만 적용, 나머지(다른 스테이지·방·시즌 전쟁)는 off. 둘 다 비면 전체 적용이므로 on 은 반드시 목록과 함께 켠다. 단 방만 켜려면 STAGES에 존재하지 않는 값을 넣지 말고 ROOMS만 지정하면 스테이지는 off가 된다.
2. config 반영: `php artisan config:clear`(캐시를 쓰는 경우) 후 서버 재기동(artisan serve 는 .env 변경 시 자동 재시작 없음).
3. 반영 시점: 새 전투 생성 시 `state.micro_mode`에 고정된다. 진행 중 전투·세이브는 기존 값 유지. on 확인은 attack 이벤트의 `micro.mode === 'on'`.
4. 롤백: `GAME_MICRO_MODE=off`(또는 변수 삭제) 후 재기동. 새 전투부터 off. 이미 on 으로 시작한 전투는 그 전투가 끝날 때까지 on 이므로 필요하면 해당 전투를 폐기. shadow 로 돌리려면 `shadow`.
5. FE 게이트: `battleStore`가 `attack.micro.mode === 'on'`일 때만 `micro`를 컷신에 넘긴다(shadow·off·필드 없음은 기존 연출). 액티브 스킬 교전은 서버가 미시 제외, 배 탑승 교전은 `BattleCutscene`(`shipOn`)이 기존 컷신으로 폴백한다.
6. 해전 주의: on 이면 수군 교전도 서버는 미시 결과(`hp_after`)로 맵 HP를 확정하고(수군 이동 유형 naval 속도 사용, 수상 배율은 damageInfo 반영), 컷신만 배 탑승 유닛이 낀 경우 구 컷신이다. 즉 해전 on 시 연출은 구 컷신, 수치는 미시. 해전 스테이지는 on 목록에서 빼는 것을 권장.

### 12.3 원거리 제자리·접촉 속도·타격 후 복귀 (2026-11-06)
- `ranged_hold`(config true): 원거리 병사(영웅 제외)는 `ranged_hold_ticks`(30) 전개 구간 이후 이동 없이 사거리 안 표적만 선정·사격한다. 사거리 밖이면 매 틱 재선정하며 대기, 사거리 안 표적이 없으면 피해 없이 정상 종료(교착 아님). 끄면 기존.

- `hit_and_return`(config true): 연출 전용 `rt`=[[틱, 개체, 타격x, 타격y, return_ticks, 0, 타격x, 타격y]] (보병·창·검만, 기병은 아래 돌격 규칙이라 제외). 서버 결과(HP·타깃·이동)는 불변(테스트로 확인). FE는 타격 시점에 s 의 배치 위치로 return_ticks 동안 복귀 후 다음 타격 전 재접근,
- 엔진 규칙(복귀 이동 중 비타격, 기병 1회 돌격 타격 상한)은 구현하지 않았다. 병사 이탈로 접촉/타격 수가 크게 바뀌어 shadow 일치율이 더 떨어질 것으로 판단.
- **기병 단일 돌격(`cavalry_charge`, config true, 엔진 규칙)**: 영웅 제외 기병(mounted 근접)은 교전당 딱 1번, 개체별 출발 지연(attack_phase) 후 자기 y 고정 직선으로 적 쪽으로 질주한다. 경로상 `charge_lane`(100) 이내·사거리 안에 들어온 적을 지나며 1회씩 타격(개체당 `charge_hit_cap`=3 상한)하고, 모든 생존 적의 x 를 지나쳐 빠져나가면 배치 위치로 복귀(이동만)한 뒤 끝난다(재돌격·복귀 후 타격 없음, 표적 부착 없음). 위치는 기존 `k`(속도 변경 시 위치 기록)에 그대로 남는다: 돌격 시작 -> 관통 끝 방향 전환(복귀 시작) -> 홈 도착 정지. 방향 전환 시점 별도 기록 불필요. 끄면 기존 접촉 교전.

- `formations_enabled`(MicroCombat DEFAULTS·config `game.rules.micro`, 기본 false): false 면 모든 영웅·부대가 중립 기본 격자(grid2x5)로 처리되어 진형 속도 감속·접촉 cap·`ranged_cap`·타깃·진형 상성 순환·`speed_pct_by_move`(진형별)가 모두 비적용이고, 결과·이벤트에 `formation`/`formation_ko` 필드를 내보내지 않는다(FE `formation_ko` 는 없으면 빈 배열로 처리). 진형 데이터(`hero_formations.json`)·`FormationBook`·`FORMATIONS`·`formation_rules` 코드는 그대로 두었고 `formations_enabled=true`로 복구한다. 진형 의존 테스트는 플래그 on 으로 실행한다.
- 영향 없음: 구 전투 Engine 의 `T_FORMATION` 패시브(인접 아군 수 기반)는 micro 진형과 무관한 별개 기능이라 건드리지 않았다. 영웅 API 는 micro 진형을 노출하지 않는다(응답의 `formation` 은 squad 배치 정보). 스테이지 데이터의 `enemy_squad.formation` 값은 유닛 state 에 남지만 플래그 off 에서는 사용되지 않는다.

### 12.5 기본 배치 stagger343 (2026-11-07)
- `default_layout`(기본 `stagger343`, 구 배치는 `grid2x5`로 복구): 진형 비적용 시 10기 기준 3-4-3 비스듬한 대형. 열 0(앞, 적 쪽) 3명 / 열 1(중) 4명 / 열 2(뒤) 3명, 중열은 행이 반 칸(75) 어긋난다. 좌표는 `x = 300 - 열 x spacing_x`(공격측), 방어측은 `600 + 열 x spacing_x`(좌우 반전), `y = 행 x spacing_y`(0~600).
- 공격측 10기 슬롯(개체 번호 순 = 채움 순서): 0:(300,300) 1:(300,150) 2:(300,450) 3:(150,225) 4:(150,375) 5:(150,75) 6:(150,525) 7:(0,300) 8:(0,150) 9:(0,450). 방어측은 x 가 600/750/900, y 동일. 병력이 적으면 앞 번호부터 채운다.
- **생존 병사 HP 초기화(2026-11-07, `survivor_reset`, config true / 코드 기본 false)**: 교전이 끝나면 살아남은 병사 개체(HP 1 동시전멸 방지 생존 포함, 영웅 개체 제외)의 HP를 개체 최대 HP(`m`)로 복구한다. 쓰러진 병사만 손실이며 `hp_after` = 생존 병사 수 x (max_hp/10) 올림 환산(원래 HP 초과 불가, 생존 시 최소 1), `alive`·`e`도 복구값 기준이다. 사망 판정·타격 기록 `h`(타격 시점 잔여 HP)는 불변이라 컷신은 재생 중 막대가 낮아졌다가 종료 정합(`e`)에서 풀로 돌아온다. 영웅 개체는 기존 `hero_hp_mult` 환산 유지. false 면 기존 동작.
