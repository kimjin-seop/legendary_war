# 가로 폰(landscape phone) 대응 계획 (윤프론, 2026-11-04)

코드 감사 결과와 수정안이다. **아직 코드는 고치지 않았다.** 사용자 확인 후 단계별로 진행한다.

## 1. 대상 해상도와 실제 논리 크기

`layout.js computeLayout` 규칙은 다음과 같다.
- UI 배율 `ui = clamp(짧은 변 / 1080, 0.6, 2)`
- 1 unit = `ui x 1.5` CSS px
- 논리 크기 `lw/lh = CSS 크기 / (ui x 1.5)`

폰은 짧은 변이 375~430이라 모두 하한 0.6에 걸린다. 그래서 1 unit = 0.9 CSS px이 된다.

| 화면(CSS) | 논리 lw x lh | L.portrait | L.cls | L.dense(lh<600) | 지금 씬들이 고르는 배치 |
|---|---|---|---|---|---|
| 1280x720 (기준) | 1280 x 720 | false | tablet | false | 데스크톱 |
| 390x844 (세로 폰) | 433 x 938 | true | phone | false | 모바일(세로) |
| 844x390 (가로 폰) | **938 x 433** | false | phone | true | **데스크톱**(lw >= 760·900) |
| 932x430 (가로 폰) | **1036 x 478** | false | phone | true | **데스크톱** |
| 667x375 (가로 폰) | **741 x 417** | false | phone | true | 씬마다 다름(lw < 760이면 일부만 모바일) |

결론은 두 가지다.
- 가로 폰은 높이가 417~478 unit밖에 안 되는데, 대부분의 씬이 "폭 760·900 이상 = 데스크톱"으로 판정한다. 그래서 높이 720을 전제로 한 데스크톱 배치를 짧은 높이에 그대로 쓴다. 이것이 핵심 원인이다.
- 667x375(lw 741)는 Gacha처럼 `lw < 760`을 모바일로 보는 씬에서는 세로 폰용 배치(세로로 쌓기)를 쓴다. 높이가 417밖에 없어 더 크게 깨진다.
- 노치와 세이프 영역은 `L.safe`(env(safe-area-inset-*))로 이미 읽는다. 다만 가로에서는 좌우 인셋(약 47pt=52 unit)이 커지는데, 일부 화면만 `safe.l/r`을 반영한다.
- 글자: 12 unit = 10.8 CSS px, 11 unit = 9.9 px. 세로 폰과 같은 값이라 새 문제는 아니다. 그러나 가로 폰에서는 화면을 맞추려고 글자를 더 줄이는 코드(shrinkToFit 최소 9 등)가 겹치면 8px대까지 내려간다.

## 2. 문제 목록 (우선순위)

### 심각 (플레이 불가·주요 버튼 가림)

1. **로비 공통 크롬이 높이의 30% 이상을 차지함** (`scenes/Lobby.js`)
   - 상단 바 72와 하단 탭 56(+safe.b), 본문 여백 24, 서브 탭 46을 합치면 433 중 약 200이 크롬이다. 탭 본문은 약 235 unit만 남는다.
   - 스테이지 지도(StageMapView 와이드 배치)·영웅 상세·상점 목록이 모두 이 높이에 갇힌다.
2. **뽑기 메인(Gacha)이 데스크톱 배치를 고름** (`scenes/Gacha.js`, mobile = `L.portrait || L.lw < 760`)
   - 844x390에서 콘텐츠 높이 AH는 약 305이다. 그런데 타이틀 크기 기준 `TH = max(AH, 520)`이 520이라, 타이틀 묶음(1.5배)만 높이 약 150을 차지한다.
   - 영웅 초상(AH x 0.98)·이름표(58%)·하단 HUD(버튼 64·천장 게이지·상세/확률 44)가 같은 300 안에서 겹친다. 왼쪽 배너 목록(AH x 0.62)과 하단 버튼 줄도 겹친다.
   - 667x375는 모바일(세로 쌓기) 배치라 영웅 묶음이 HUD 뒤로 숨는다(강화면 gacha39 회귀와 같은 유형).
3. **전투 컷신 하단 패널 비율** (`fx/BattleCutscene.js`)
   - 데스크톱 기준 PH = min(210, max(184, H x 0.27)) = 184이다. 433 중 42%가 패널이고, 무대 SH는 249뿐이다.
   - 영웅 스프라이트 크기 `H x 0.17` = 74, 병사 `H x 0.125` = 54는 H 기준이라, 무대 높이 249 안에서 바닥선(0.78 SH = 194) 위 공간이 빠듯하다. 화살 정점 상한(cutApexTop)도 무대 밖으로 나갈 수 있다.
4. **모달 높이 상한과 본문 넘침** (`ui/Modal.js h = min(h0, L.lh - 24)` = 409)
   - 본문이 긴 모달은 높이가 잘리지만 본문 스크롤이 없어 글이 버튼 줄 뒤로 들어간다. 대상: 영웅 상세 720, 확률 정보, 공지, 소탕 결과 등.
   - 영웅 상세(`heroDetail H = min(720, lh - 24)`)는 W >= 760이라 좌우 배치(초상 280 + 스프라이트 박스 128)를 고른다. 그러면 초상이 bodyH - 140 안으로 줄어 스크롤 영역이 거의 남지 않는다.
5. **전투 HUD의 선택 유닛 카드와 초상** (`scenes/Battle.js battleLayout`)
   - 데스크톱 분기: 카드 124 + 초상 portMax `lh x 0.22` = 95(dense 처리는 있음), 하단 턴 종료 52 + 정보 바 30 + 도구 48, 상단 칩 줄 56이 있다.
   - 지도 가시 높이는 약 433 - 56 - 136 ≈ 240이다. 카드가 좌하단 맵을 크게 가린다.
   - 컨텍스트 메뉴(행동 4개 x 44 + 여백 ≈ 200)와 예측 말풍선이 popup bounds 안에서 위아래로 들어갈 자리가 부족하다.

### 중간 (보이긴 하지만 불편·일부 잘림)

6. **대사(Dialogue) 씬**: 하단 어둡게 띠 `lh x 0.55`와 대사창·이름판·선택지 버튼 높이가 데스크톱 고정값이다. 가로 폰에서 초상·배경이 위쪽 약 190 unit에 몰린다. 선택지가 3개 이상이면 대사창 위로 넘친다.
7. **시즌 전쟁(War)**: 로비 크롬 아래 rect 높이가 약 230이다. 지도 상자와 영토 정보 패널(데스크톱은 좌우 분할)이 이 높이에 맞춰 줄어, 지도 핀·라벨이 겹친다. 시나리오 선택 줄(46)이 있으면 더 좁아진다.
8. **스테이지 지도(StageMapView)**: `mobileMap = L.portrait || L.cls === 'phone'`이라 가로 폰은 모바일 지도 에셋을 쓴다. 반면 `wideLayout`(lw >= 900 가로)은 데스크톱 사이드 패널이다. 에셋과 배치가 서로 어긋나고, 사이드 패널 요약 sumH와 스테이지 목록이 235 높이에 갇힌다.
9. **설정 모달**(`ui/SettingsModal.js h = min(lh - 24, 470)`): 행이 8개 이상이면 아래 행이 잘린다. 스크롤 확인이 필요하다.
10. **결과창(Battle 결과)**: `lowH = lh < 560 && lw >= 760` 처리가 이미 있어 2열 배치를 쓴다. 다만 보상·레벨업 칩 행이 많으면 버튼이 잘리는지 확인이 필요하다.
11. **가로 노치 세이프 영역**: Gacha·War·StageMapView의 일부 좌표는 `L.safe.l/r`을 쓰지 않는다. 노치 쪽(좌 또는 우 약 52 unit) 가장자리 버튼과 칩이 노치 아래로 들어간다.

### 낮음

12. 툴팁(커서 툴팁·버튼 툴팁)은 가장자리 뒤집기가 있어 대체로 괜찮다. 다만 터치 가로 폰에서는 터치 대체 고정 팝업(2.2초)이 지도 중앙을 가린다.
13. 글자 최소 크기: `shrinkToFit` 하한 9~12 unit이 가로 폰에서 8~11 CSS px가 된다. 하한을 CSS px 기준(예: 10px)으로 바꾸는 공통 함수가 필요하다.
14. 회전(orientationchange)은 `watchLayout`이 150ms 디바운스로 처리하고, 각 씬은 `relayoutOnChange`로 재시작한다. 동작은 문제없다. 뽑기·시즌 전쟁 오버레이는 로비가 재시작하며 다시 띄운다. 회전 중 컷신이 재생되면 씬이 재시작돼 컷신이 끊기는 것은 확인이 필요하다.

## 3. 수정안

### A. 공통 'short' 모드 도입 (layout.js, 1단계)
- `computeLayout`에 `L.short = !L.portrait && L.lh < 560`(가로 폰·낮은 창)을 추가한다. 같이 `L.compactH = L.lh < 640` 정도의 단계값도 둔다.
- 각 씬의 배치 판정을 "폭 기준(lw < 760)"과 "높이 기준(short)"으로 나눈다.
  - 폭이 넓고 높이가 짧으면 **가로 배치(좌우 분할) + 높이 압축**으로 간다.
  - 세로 쌓기 배치(모바일)는 `L.portrait`일 때만 쓴다(667x375가 세로 쌓기로 가지 않게).
- 공통 상수표(`layout.js` 또는 `ui/metrics.js`)를 둔다.
  - 상단 바 높이: 72 → short 48
  - 하단 탭 높이: 56 → short 44(+safe.b)
  - 서브 탭: 46 → short 36
  - 본문 여백: 12 → short 6
  - 버튼 최소 높이: MIN_TOUCH 44 CSS px 유지 = 49 unit
- 글자 하한 공통 함수를 둔다. `minFont(px) = ceil(px / (ui x 1.5))`로, CSS 10px 아래로 내려가지 않게 한다.

### B. 씬별 (2단계, 심각 순)
1. **Lobby**:
   - short이면 상단 바를 48로 줄이고 프로필 패널을 1줄로 접는다(EXP 바 숨김).
   - 하단 탭을 아이콘 위주 44로 줄인다.
   - 그룹 서브 탭은 상단 바 오른쪽 빈 자리에 인라인으로 넣는다(별도 줄 없음).
   - 그러면 본문이 약 235 → 약 320 unit으로 늘어난다.
2. **Gacha**:
   - `mobile` 판정을 `L.portrait`로 바꾼다(가로는 항상 좌우 배치).
   - short일 때:
     - 타이틀 기준 `TH = AH`(520 하한 제거), 타이틀 묶음 1.0배
     - 영웅 초상 높이 `AH x 0.9`, 이름표 높이 50%
     - 하단 HUD는 버튼 1줄(1회·10회 높이 48) + 천장 게이지를 버튼 위 한 줄로 압축
     - 상세/확률은 오른쪽 위 작은 버튼으로 이동
     - 배너 목록은 왼쪽 세로 칩(제목만, 부제 생략)
3. **BattleCutscene**:
   - short일 때 패널 PH = 120(1줄 게이지 + 이름·병력 숫자 1줄, 능력치 표는 좌우 2열 1줄 요약이나 생략)
   - 무대 SH = 313으로 늘린다.
   - 병사·영웅 크기 기준을 H가 아니라 SH로 바꿔 SH x 0.23·0.31로 둔다.
   - 초상은 생략하거나 패널 높이에 맞춰 작게 한다.
4. **Modal**:
   - 본문이 영역을 넘으면 본문만 ScrollList로 감싸는 공통 처리를 넣는다(버튼 줄 고정).
   - short일 때 모달 폭을 넓히고(최대 lw - 24) 높이를 lh - 12로 쓴다.
   - 영웅 상세는 short일 때 좌(초상 축소 lh x 0.45 + 스프라이트 박스 옆으로) / 우(스크롤 섹션)로 바꾼다.
5. **Battle HUD**:
   - short일 때 선택 유닛 카드를 1줄 정보 띠로 바꾼다. 높이 60, 큰 초상은 생략하고 작은 원형 초상만 둔다.
   - 턴 종료와 도구 줄을 하단 한 줄(48)로 합치고, 정보 바는 상단 칩 줄 옆으로 옮긴다.
   - 컨텍스트 메뉴는 2열(2x2)을 우선한다(이미 narrow 판정이 있으므로 short도 포함).
6. **Dialogue**: short일 때 대사창 높이를 고정 비율 대신 글자 3줄 + 이름판으로 줄이고, 선택지는 대사창 오른쪽 세로 목록으로 바꾼다.
7. **War / StageMapView**:
   - short일 때 정보 패널은 오른쪽 사이드 고정(폭 36%)에 지도 왼쪽을 쓴다.
   - 시나리오 선택 줄은 상단 바(서브 탭 줄) 오른쪽으로 옮긴다.
   - StageMapView는 `mobileMap` 판정을 `L.portrait`로 바꿔 에셋과 배치를 일치시킨다.
8. **세이프 영역**: 가장자리 고정 요소(Gacha 목록·HUD, War 바, 전투 상단 칩·도구, 컷신 패널 텍스트)에 `L.safe.l/r`을 일괄 반영한다.

### C. 검증 (강화면)
- 해상도 5종: 844x390, 932x430, 667x375(노치 시뮬레이션 safe-area 좌 47), 1280x720, 390x844
- 화면: 로비 각 탭, 뽑기 메인·결과, 전투 HUD·행동 메뉴·예측·결과, 교전 컷신, 대사, 시즌 전쟁, 영웅 상세, 설정 모달
- 기준: 주요 버튼(출정·턴 종료·소환·확인)이 가려지거나 잘리지 않을 것, 본문 스크롤 가능, 글자 CSS 10px 이상, 세로 폰·데스크톱 회귀 없음

## 4. 진행 순서 제안
1. A(공통 short 모드·상수·글자 하한) + Lobby 크롬 압축: 모든 탭에 효과가 있어 먼저 한다.
2. Gacha, BattleCutscene, Modal 본문 스크롤(심각 2~4)
3. Battle HUD(심각 5)
4. Dialogue, War, StageMapView, 설정·결과(중간)
5. 세이프 영역 일괄 반영, 글자 하한 점검(낮음 포함)

각 단계 뒤에 강화면 실화면 검증을 한다. 세로 폰(390x844)과 데스크톱(1280x720)은 `short = false`라 기존 배치 그대로여야 한다(회귀 확인 필수).
