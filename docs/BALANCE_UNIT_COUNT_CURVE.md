# 적 유닛 수 곡선 설계: 초반 3~4 -> 후반 한쪽 20 (임밸런, 시작값/튜닝 대상)

작성: 임밸런, 2026-11-03. 범위는 **데이터 설계 문서뿐**이다. 게임 데이터 JSON·엔진 코드·DB·시드는 수정하지 않았다. `game:simulate`는 **실행하지 않았다**(사용자 지시: 최종 일괄 재측정). 따라서 이 문서의 모든 수치는 설계 가정(시작값)이며 승률·평균 턴·밀도 적합성은 **미측정**이다.

표기: [사실] = 파일·코드에서 읽음 / [산술] = 사실에서 계산 / [가정] = 설계 판단, 측정 필요.

## 0. 용어와 전제

- **"부대" = 진영 한쪽 전투 유닛 수**로 쓴다. 사용자가 2026-11-03 확정한 해석이다("한쪽 유닛이 20개"; `docs/PLAN_MAP_SCALE_UP.md` 1절). `STAGES_ENEMY_V3_SPEC.md`의 "부대 = 지휘관 1 + 병사 n"과 다르므로, 표에는 squad(지휘관 단위) 수를 별도 열로 둔다. [사실]
- 적 유닛 수 산정 [사실]: ch1·legacy6·ch18/21/22는 각 JSON의 `enemy_units_initial`/`enemy_units_peak`(증원 포함)를 그대로 썼다. 검증: ch1_s1~s10·stage_01~06은 `enemy_squads[].units_total` 합과 `enemy_units_initial`이 전부 일치했다. ch101~104(`stages_main_a1~a4.json`)는 `enemy_squad`의 지휘관 1 + `units[]` + `squads[]`(각 지휘관 1 + `units[]`) 합을 직접 셌고, 이 4개 파일 중 a1·a4의 triggers는 비어 있고 a2·a3도 spawn 트리거가 없어 증원은 0으로 봤다.
- `*_additions.json`(송서사 지휘관 이름 치환)은 시드 시 `enemy_squads`를 같은 유닛 총수로만 치환하게 되어 있다(`GameSeedImjin10::applyNamed`가 총수 불일치 시 중단). 따라서 유닛 수 표는 v3 파일 값이 기준이다. [사실]
- 엔진 한도 [사실, `config/game.php`]: 적 초기 편성 `max_units_enemy_stage`=24, 증원 포함 생존 `max_alive_per_side_stage`=28, 아군 `max_units_per_side_stage`=24, 하드 캡 `max_units_hard_cap`=32, 영웅당 부대 `troop_slots` Lv1~9=2 / 10~19=3 / 20~=4, 캠페인 출격 슬롯 `campaign_slots` 유저 Lv1~2=2, 3~4=3, 5~6=4, 7~8=5, 9~=6.
- **한쪽 최대 20 = 초기 편성 상한**으로 잡았다. 증원 포함 최대는 보스·생존 스테이지에서 24(엔진 28 한도 아래 여유 4)다. [가정]
- 이동력 [사실, `unit_types.json` 현재값 vs `.bak-move-20261103`]: 검·창·치유·수병 4->6, 기병·비행 6->8, 궁·마법 4->5, 중장갑 4(변동 없음). 이미 반영되어 있다.
- 적 레벨 [사실, `BattleService.php:126-127`]: 실제 적 레벨 = `enemy_level + enemy_level_offset`(최소 1). 부대 성장률 `troop_growth_pct`=3%/레벨.
- 아군 유닛 가정 [산술]: 영웅 1 + 부대(troop_slots)이므로 영웅 Lv1~9는 영웅당 3유닛, Lv10~19는 4, Lv20~는 5. 출격 영웅 6 x 4 = 24가 아군 상한과 맞물린다.
- 한계 [사실]: stage_01~06의 목표 타입은 `stages.json`에 명시 필드가 없어 표에서 "미확인"으로 표기한다. 맵 크기는 `maps*.json`의 `tiles`(행 x 열) 크기이며 ch18/21/22는 스테이지 파일의 `map_size`를 썼다. 같은 맵 코드가 여러 스테이지에서 재사용된다(pk_20 3회 등).

## 2. 목표 곡선

곡선은 장 번호가 아니라 **권장 레벨 L**로 정의한다. 임진 1장(L1~9), 오리지널 4막(L1~20), 서가 장(L10~22)이 같은 레벨 축에서 겹치기 때문에 이렇게 해야 어느 경로로 들어와도 같은 체감이 된다. [가정]

## 3. 이동력 상향·맵 확장과 맞는 레벨 오프셋 변화 방향 가이드

수치 확정은 시뮬 대상이며, 여기서는 **방향과 폭**만 적는다. [가정]

### 3-1. 원칙
1. **수로 맞추던 난이도를 오프셋으로 보정하지 않는다.** 레벨 +1은 부대 스탯 약 +3%뿐이다([산술]). 예를 들어 적 유닛이 40% 줄어든 것을 오프셋으로 메우려면 +10레벨 이상이 필요한데 이는 비현실적이다. 따라서 초반 스테이지는 "더 쉬워진다"를 받아들이고, 승률 밴드를 위로 이동(L1~4 밴드 90%+)시키는 것이 정직하다.
2. **오프셋은 적/아군 비 R로 정한다**: R <= 0.67이면 +1~+3(위협 유지), 0.67~0.85이면 0 근처(-1~+1), R > 0.85이면 -1~-3. 어느 경우든 **|오프셋| <= 3**을 목표로 한다.
3. **현재 큰 오프셋은 정리 대상이다**: ch1_s5 +10(실제 적 Lv16 vs 권장 5), ch21_s8 +7, ch18_s3 +5, ch1_s2·s4 +4, ch21_s2 +4, stage_03 +4 는 모두 "적 수를 많이 두고 개별 적을 키워 밴드를 맞추던" 값이다. 적 수가 줄어드는 ch1_s2~s6, stage_03은 +4~+10이 과대(축소 방향), 반대로 적 수가 늘어나는 ch104·ch103·ch18 전반은 음의 오프셋(-5 이하)이 아니라 0 근처로 둔다.
4. 음의 오프셋(ch22_s1·s4 -5, ch18_s8 -4, ch21_s4 -4, ch1_s9 -3 등)은 "적이 많아 개별 적을 약하게" 만든 것이다. 20 이하로 수를 줄이는 스테이지(ch22_s7 24->18, ch22_s5 24->13/23, ch21_s2 24->19)는 이 음수를 0 쪽으로 올려 총 위협을 유지한다. 단 수 감소폭이 큰 순서(ch22_s5, ch22_s7)가 먼저다.

### 3-2. 이동력 6(보병)·기병 8과 맵 크기
- 접촉까지 걸리는 턴 = ceil((적-아군 최소 거리 - 사거리) / 이동력). 보병 6이면 맨해튼 12는 약 2턴, 19(후반 36x26)는 약 3턴, 기병 8이면 각각 2턴·3턴이다. 맵 확장은 거리 증가를 만들고 이동력 상향이 이를 상쇄한다. 설계 기준: 중반 최소 거리 12 이상, 후반 16 이상(`PLAN_MAP_SCALE_UP.md` 3절과 동일). [산술]
- 생존형(`survive_turns`)은 접촉이 늦어지므로 방어 시간 = 접촉 턴 + 4~6턴이 되도록 **목표 턴을 8->10~12로 연장**하거나 적이 첫 턴부터 접근하도록 배치한다. 현재 survive: ch1_s4(8), ch1_s6(10), ch101_s4(8), ch102_s4(8), ch21_s8(8), ch22_s5(10). `max_turns`는 30이므로 상한 안이다. [가정]
- 점령형은 점령 지점이 적 진영에 가깝게 위치해 아군이 2~3턴 안에 도달하도록 둔다(이동력 6 기준 거리 12~18).
- 궁수(이동 5)·중장갑(이동 4)이 큰 맵에서 뒤처지는 문제: 아군 편성이 보병 위주로 쏠릴 가능성이 높다. 후반 맵에는 고지·마을 등 엄폐 거점을 중간 거리에 두어 느린 병종이 합류할 거점을 만든다(맵디자이너 협의).
- 3~4배 면적 확장은 적 유닛이 많은 구간(L8 이상)부터 적용하고, 초반(적 3~5)은 현행 크기를 유지하는 것을 제안한다. 3유닛 대 6유닛이 3배 면적에서 만나면 이동만 길고 교전이 비는 것이 우려된다. [가정, 사용자 결정 필요]

- ch102_s5·ch103_s3·ch21_s1·ch21_s2·ch18_s1은 현재 16x12 맵인데 제안 적 수가 13~19라서 **맵 교체가 사실상 필수**다(면적 4배 이상). 맵 코드 재사용(pk_01, pk_02, pk_13, pk_18, pk_20 등)이 많아 신규 맵 수는 대략 스테이지 수의 60% 이내로 줄일 수 있다.

## 5. 적용 순서 제안 (데이터 반영 시)

1. 맵 확장 매핑(맵디자이너)이 나온 뒤, 스테이지별 적 편성을 **한 번에 한 챕터씩** 교체한다(ch1 -> stage_01~06 -> ch101~104 -> ch18 -> ch21 -> ch22). 변경 전 해당 JSON 백업, 개발 DB에만 멱등 시드.
2. 유닛 수를 먼저 바꾸고, 오프셋·hp_mult는 최종 일괄 측정 후 3절 방향대로 5% 이내 소폭씩 조정한다(변수 한 그룹씩).
3. 보스·막 마지막 스테이지를 마지막에 확정한다(증원·페이즈 트리거가 얽힘).

## 6. 측정 계획 (최종 일괄 재측정 시)

이번에는 측정하지 않았다. 최종 재측정에서 확인할 것: 스테이지별 승률(밴드: L1~4 90%+, L5~9 70~80%, L10 이상 55~65%, 보스 45~55% — 모두 가정), 평균 라운드·턴 제한률, 선후공 편향, 첫 턴 격파율, 치유 사용, 20 대 20 봇 처리 시간. 시뮬은 일반 지휘관·가변 부대·맵 지정이 필요하며 현재 `game:simulate`가 이를 지원하는지는 `STAGES_ENEMY_V3_SPEC.md`(STAGES_CH1_SPEC 8절 6번)에 미지원으로 적혀 있어 확인이 필요하다.
