# 타일 교체 + 맵 설계 브리프 (사용자 요청, 2026-11-02)

사용자 요청: "타일 퀄리티가 많이 떨어져 첨부한 타일 이미지로 교체". 원본 이미지: `D:\다운로드\PC _ Computer - RPG Maker 2003 - Exclusive Content - Exclusive Tilesets 2.png` (966x520, 체크섬은 작업 시 기록). 4개 칩셋(좌상=기본 필드/성/가구, 우상=용암·눈·동굴, 좌하=필드·눈·숲, 우하=성벽·목조·농지·정원) 구성으로 보임. 분홍(마젠타) 배경은 투명 처리 대상.
(법무 주의: RPG Maker 2003 기본 칩셋은 제3자 저작물일 수 있음. 사용자 정책상 개발은 막지 않고 공개 전 라이선스 확인 메모로만 남긴다.)

## 역할 지시(사용자 원문 요약): 15년차 SRPG 레벨 디자이너 + 픽셀 타일맵 엔지니어
1. 타일셋 분석 먼저: 실제 크기·격자·타일 ID·연결 규칙 확인(이미지만 보고 좌표 추측 금지). 기본 32x32, 실제 규격이 다르면(RM2003 칩셋은 16x16 가능) 확인·보고 후 정수배 확대(최근접). 지형/건축물/장식/연결/모서리 분류, 다타일 구조물은 하나의 논리 오브젝트, 상하좌우 연결 가능/불가 규칙, 타일셋에 없는 구성요소를 임의 제작 금지, 부족 타일은 명확히 보고.
2. 공간 설계 원칙: 모든 공간·오브젝트에 기능과 존재 이유(성=성벽·성문·감시탑·내부, 마을=주거·시장·광장·통행로, 숲=군집, 창고=출입구·상자·통, 시장=상점·진열대). 잘못된 예: 잔디 한가운데 촛대, 출입구 없는 건물, 길과 안 이어진 집, 끊긴 성벽, 못 가는 계단, 물 위 가구, 구조적으로 안 맞는 지붕 조각.
3. 건축물은 다타일 조합(주택 4x4~8x6, 대저택 8x8~12x10, 성문 6x5+, 성채 12x12+). 지붕·벽·출입구 일치, 연결부 단절 없음, 비율 자연스러움, 출입구 앞 통행 공간, 도로·광장 연결.
4. 제작 순서: ① 공간 기획 ② 전체 레이아웃(길·출입구·이동 영역) ③ 건축물 조립(지붕·벽 정합, 성벽·성문 연결) ④ 오브젝트 배치(군집, 과장식 지양, 동선 비가림) ⑤ 최종 검증(구조 오류·개연성·타일 연결·이동 경로·시각 균형), 오류 시 수정 후 재검증.
5. 사람이 설계한 듯: 반복 패턴 회피, 집 방향/크기 변화, 목적지를 잇는 자연스러운 도로, 군집 숲, 위계, 구역별 장식 밀도 차이, 빈 공간 전부 채우지 않기.
6. SRPG 규칙: 주요 경로 연결, 이동 불가 지형 명확, 충돌 영역, 엄폐/병목, 좁은 길/넓은 전투 공간 균형, 고저차·계단·다리 연결성, 고립된 이동 가능 타일 금지.
7. 구현/검증: 맵 데이터를 레이어(지형/건축물/오브젝트/전경/충돌·이동)로 구조화 관리. 검증 도구로 타일 인덱스 유효성, 연결 관계, 건축 규칙, 오브젝트 배치 가능 지형, 이동 가능 연결성, 출입구·계단 접근성 검사. 실제 렌더링 결과를 보고 어색한 부분 수정.
8. 결과물: 맵 이미지, 수정 가능한 타일맵 데이터, 타일 ID 매핑, 이동/충돌 정보, 구역·동선 설계 문서, 검증 결과와 남은 제약.
최우선 원칙: 모든 건축물·지형·오브젝트는 그 위치에 있을 합리적 이유가 있어야 함.

## 프로젝트 적용 시 유의
- 기존 전투 맵은 기존 타일 에셋/지형 코드(TERRAIN 등)와 연동되어 있다. 새 타일셋을 '지형 코드→타일 ID' 매핑으로 연결하고 기존 지형 규칙(이동 비용·방어)과 충돌하지 않게 한다. 먼저 현재 타일 로딩·렌더링 구조(assets.js, 전투 맵 렌더)를 분석해 교체 지점을 확정한다.
- 매니페스트 병합은 docker/gemini/merge_fragments.mjs로만. build_manifest.mjs 금지. 기존 타일은 백업 후 교체(교체 스위치 가능하게).
